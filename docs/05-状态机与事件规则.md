# 05 状态机与事件规则

对应实现文档第 5~8 节。实现位置：`app/oilcheck/pipeline.py`、
`app/oilcheck/types.py`。

## 1. 设计原则

- 现场工艺只有两个判定点：**取料完成** 与 **人工二次涂油完成**；
- 只对这两个判定点发 `CONFIRMED` 事件；唯一的异常判定是**漏涂 NG**：
  取料后二次涂油没完成就来了下一次取料。不做槽位识别，不做放料判定；
- 视觉 Track ID 只做画面标注与短时关联，跨帧判断由作业周期维护；
- 事件使用视频时间戳，不用帧序号计算时长；
- 示例回放用**媒体时间**（每帧前进 `1/native_fps`）而不是墙钟时间：变速播放
  不改变判定结果，暂停不产生时间空洞，循环回绕也不会让时间倒退。实时相机
  没有媒体时间，回退到墙钟时间。

## 2. 状态域

### 2.1 任务阶段 TaskStage

| 值 | 含义 |
| --- | --- |
| `WAITING_PICK` | 等待取料 |
| `PICKED` | 已取料，等待人工二次涂油 |
| `OILED` | 本周期的涂油已完成，周期结束 |

```text
WAITING_PICK ──PICK──> PICKED ──MANUAL_OILING──> OILED
       ▲                                            │
       └──────────── 周期复位，等待下一次取料 ────────┘
```

### 2.2 最终结果 TaskResult

| 值 | 含义 |
| --- | --- |
| `PROCESSING` | 周期进行中（等待取料 / 等待涂油） |
| `COMPLETED` | 涂油完成，周期结束 |
| `NG` | 已取料但二次涂油未完成就等来了下一次取料（漏涂） |

### 2.3 事件类型 EventType

| 值 | 标签 | 结果 |
| --- | --- | --- |
| `PICK` | 取料 | `CONFIRMED` |
| `MANUAL_OILING` | 人工二次涂油 | `CONFIRMED` |
| `OILING_MISSING` | 人工二次涂油未完成（漏涂） | `NEEDS_REVIEW` |

历史事件文件里可能还有 `PUT` / `BRUSH_CONTACT` / `TASK_RESULT`：读取时保留原
字符串并标为「（历史）」，不会误标成 `PICK`。

## 3. 每帧证据

- 手部轨迹中心是否在涂油盘区内（轨迹移出工作追踪区后仍继续跟踪）；
- 手里是否拿着丝杆（`hand_screw_max_distance` 内最近的丝杆检测）；
- 手持丝杆的位置（该手 `held_infer_distance` 内最近的丝杆检测）；
- 刷头工作点到丝杆中心的归一化距离；
- 上述状态的持续时间（基于视频时间戳）。

## 4. 取料判定

### 4.1 进盘

某只手中心第一次进入涂油盘区（`tray_roi` 并上 `oil_station` 检测框）时，
记录 `holding_on_entry`：那一刻手里是否已有丝杆。

### 4.2 离盘

同一只手中心离开涂油盘区时同时满足：

1. `holding_on_entry == False`（进盘时是空手）；
2. 此刻手里有丝杆；
3. 盘内停留 ≥ `pick_confirm_s`（滤掉从盘边划过的动作）。

→ 发出 `PICK/CONFIRMED`，周期进入 `PICKED`。

**为什么两者要取并集**：`oil_station` 检测框只框得住盘体本身（示例①里
框底 y≈372），而工人取料时手在盘体下方 100~280px（y≈422~654）——只用检测框，
取料会被全部漏掉；手工 `tray_roi` 固定不动，盘体上下移动约 250px 时会误判
「已离盘」——只用手工区也不够。两者并集：手工区覆盖手臂活动范围，检测框
跟随盘体移动。

### 4.3 不判取料的情况

| 情况 | 原因 |
| --- | --- |
| 空手进盘、空手离盘 | 没取到东西 |
| 带料进盘、带料离盘 | 例如把丝杆放回去再拿走 |
| 盘内停留 < `pick_confirm_s` | 手从盘边划过 |
| 手部轨迹消失 > `holding_lost_timeout_s` | 进盘过程作废 |

## 5. 人工二次涂油判定

存在 `PICKED` 周期时：

1. **定位手里那根丝杆（丝杆锚点跟踪，不依赖手部视觉 ID）**：
   取料那一刻锚点为空，随后每帧
   - 先取「与某个手框交叠」的丝杆检测——握着时丝杆一定被手框遮住，
     这一步把候选从满盘丝杆（间距只有 0.02~0.03）缩到手上那一根；
   - 交叠候选里取离锚点最近的，单帧位移 ≤ `screw_anchor_max_step`；
   - 手上没有交叠杆（手被挡/框偏了）才退化为纯位置连续性；
   - 都没有时在 `screw_anchor_hold_s` 内按锚点位置继续，超出才放弃；
2. 刷头工作点（关键点优先，否则按 `brush_point_offset_*` 推算）到丝杆中心的
   归一化距离 ≤ `brush_contact_distance` → 本帧计为靠近；
3. 靠近帧按 `dt` 累加；若上一帧刷子**整帧漏检**（而不是检测到但离得远），
   把这段空档一并补回，上限 `brush_hold_max_gap_s`；
4. 累计 ≥ `brush_hold_s` → 发出 `MANUAL_OILING/CONFIRMED`，周期置 `OILED`
   并结束，回到等待下一次取料。

刷子只短暂靠近（累计不到阈值）不产生事件，但已累计的时长保留，下次靠近继续累加。

### 5.0.1 为什么不跟手

手部视觉 ID 在遮挡、快速移动后会重建。示例①一个 12 秒周期里手部 ID 换了 6 次，
绑定的 ID 一旦被 ByteTrack 回收，旧实现就再也取不到丝杆位置，涂油累计停在 0
并误判漏涂（实测该周期 19.5~22.5s 刷子距杆 0.011~0.031，远低于阈值 0.06，
实际是刷了的）。

丝杆是静置物、位移小，比手稳得多，也不受「哪只手」影响，因此改用锚点跟踪。

### 5.0.2 帧率自适应

所有距离门限与容差窗口都按**实际帧间隔**放大：
倍率 = `帧间隔 / (1 / max_fps)`，上限 `frame_scale_max`（默认 4）。

- 跟踪器的中心距离门限（手/刷头/涂油盘）；
- `screw_anchor_max_step`、`screw_anchor_hold_s`、`brush_hold_max_gap_s`。

`pick_confirm_s`、`brush_hold_s` 这类**纯时间阈值不缩放**——它们本来就以秒计，
与帧率无关；缩放的只有「一个动作跨多少像素」这类帧率敏感的门限。

实测示例①：

| 有效帧率 | 改造前 | 改造后 |
| --- | --- | --- |
| 15 fps | 4 取 / 3 涂 / 1 误判 NG | 4 取 / 4 涂 / 0 NG |
| 7.5 fps | 3 / 3 / 0 | 3 / 3 / 0 |
| 3.8 fps | 0 / 0 / 0 | 3 / 3 / 0 |
| 2.5 fps | 0 / 0 / 0 | 2 / 2 / 0 |

低帧率下第一次取料可能因采样太粗整个漏掉（采不到进盘/离盘那一帧），
这是采样极限，属于预期。

## 5.1 漏涂判定（NG）

触发点是**新的取料被确认**，不是超时：

1. 当前存在 `PICKED` 周期（已发 `PICK`、还没发 `MANUAL_OILING`）；
2. 又有一次取料被确认；
3. → 上一周期置 `NG`、`final_result = NG`、`completed_at = 新的取料时刻`，
   发 `OILING_MISSING/NEEDS_REVIEW`（`reason = oiling_missing_superseded_by_pick`，
   证据带 `brush_hold_s` / `required_s` / `NEXT_PICK_BEFORE_MANUAL_OILING`）；
4. → 新取料**另起一个周期**（`TASK-xxxxxx` 递增），不复用上一周期。

新取料必须独立成周期：若沿用同一个周期，`PICK` 事件的去重键
（`PICK:pick_confirmed`）会让第二次取料连事件都不发，漏涂就完全看不出来。

判定边界：

| 情况 | 结果 |
| --- | --- |
| 涂油完成后再取下一件 | 上一周期 `COMPLETED`，不产生 NG |
| 取料后刷子累计不够就被新取料打断 | 上一周期 `NG` |
| 取料后一直不动、不再取料 | 周期保持 `PROCESSING`，**不会**自己判 NG |

因此「最后一件取走后没涂、当天再没取料」这种情况需要人工复核或设定停机
时限，算法本身不产生 NG。

## 6. 阈值调优方法

1. 用真实完整周期视频回放；
2. 先调 `pick_confirm_s`、`hand_screw_max_distance`，保证取料不漏报/不误报；
3. 再调 `brush_contact_distance` 与 `brush_hold_s`，让「刷子靠近多久算涂完」
   与现场工艺一致；
4. 若取料误报多，优先核对涂油盘区（`tray_roi`）是否把盘边划过的路径也包进来；
5. 漏涂误报多，先看被 NG 的那条周期里 `brush_hold_s` 累计到多少——如果已接近
   阈值，说明 `brush_hold_s` 偏大或刷头遮挡导致累计中断，而不是真的漏涂。

## 7. 已知限制

- 单目顶视无法证明周向覆盖或油脂附着量；
- 刷头框中心可能不代表工作端，建议使用关键点；
- 手持丝杆被完全遮挡时不累计接触时长，周期保持 `PICKED` 等待恢复；
- NG 只在「下一次取料」时结算，最后一件漏涂不会被自动判出；
- 本期未启用事件前后视频片段。
