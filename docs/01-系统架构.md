# 01 系统架构

对应实现文档第 2、10 节。

## 1. 目标与范围

把相机帧转换为单根丝杆的业务任务，并输出取料、手持、刷涂证据与最终结果。
视觉 Track ID 只做短时关联，业务任务 ID 跨遮挡维护。

## 2. 分层结构

```text
ui/                    PySide6 页面（监控、复核、录制、设备、设置、日志）
app/oilcheck/service   线程编排：取帧 → 检测 → 状态机 → 事件落盘
app/oilcheck/detector  检测器契约：null / yolo
app/oilcheck/tracker   丝杆/手/刷头/涂油盘短时跟踪
app/oilcheck/pipeline  取料事件引擎、手持任务、刷涂行为引擎、任务状态机
app/oilcheck/config    oilcheck.json 配置与旧配置迁移
app/oilcheck/events    事件 JSONL 持久化与复核
app/oilcheck/recorder  训练视频分段录制与元数据
app/camera_manager     相机会话、预览、重连
hik/                   海康 HCNetSDK 封装
```

### 模块职责

| 模块 | 输入 | 输出与职责 |
| --- | --- | --- |
| 视频接入 | 相机流 | 解码、时间戳、断流/丢帧监测 |
| ROI 管理 | 原始帧、配置 | 限定有效推理范围；物料盒排除 |
| 目标检测 | ROI 图像 | screw / hand / brush_head 等位置、角度、关键点 |
| 目标跟踪 | 逐帧检测 | 短时 Track ID，容忍短暂漏检 |
| 取料事件引擎 | 涂油盘区、手与丝杆轨迹 | 取料候选、确认或待确认 |
| 手持丝杆管理 | 取料事件、轨迹 | 业务任务、身份重关联、遮挡恢复 |
| 刷涂行为引擎 | 手持丝杆、刷头轨迹 | 接触区间、轴向运动、覆盖进度 |
| 状态机与 UI | 事件、置信度、时间戳 | 最终状态、证据、记录 |

## 3. 线程模型

- 一个轮询线程按配置帧率读取各相机最新帧；
- 每个工位一个单线程执行器执行“检测 + 状态机”，忙时丢帧，避免排队；
- 录制器自带写盘线程；
- 事件写盘在工位线程内完成（量小、需要可靠落盘）；
- UI 只读取快照与事件，不触碰检测线程。

## 4. 启动与关闭

`OilCheckService.start()` 启动轮询线程；每个工位构建检测器与
`StationPipeline`。关闭时停止录制、关闭检测器、释放执行器。

## 5. 一次检测的数据流

```text
Frame(ts, bgr)
  → Detector.detect() → FrameDetections(ts, size, detections)
  → StationPipeline.process()
      1) ROI 过滤：排除物料盒，限制在 tray/hand/brush 区域
      2) 跟踪：screw/hand/brush_head/oil_tray
      3) 取料候选：手部交互、共同运动、离盘、进入手持区
      4) 业务任务：创建/重关联/遮挡处理
      5) 刷涂：接触邻域、轴向投影、覆盖区段
      6) 任务状态机与事件
  → StationSnapshot(tasks, tray, tracks, stats)
  → EventStore.add(EventRecord)
  → UI 轮询快照
```

## 6. 关键设计决策

1. **取消槽位**：涂油盘只作为参考区域；检测到的盘体用于随动，定位不可靠时回退
   固定 ROI。
2. **视觉/业务 ID 分离**：`screw_track_id` 可变化，`task_id` 保持不变。
3. **证据链取料**：任何单一条件（手离开、丝杆消失、区域变化）都不足以确认。
4. **局部坐标刷涂**：刷头相对丝杆的轴向运动，而不是图像绝对位移。
5. **保守判定**：关键证据不可见时输出 `PENDING_CONFIRMATION`。
6. **物料盒屏蔽**：训练与推理使用一致的排除 ROI。

## 7. 与旧项目的关系

旧项目的四槽位、槽位占用、固定取料位逻辑已移除。旧配置中的
`pick_roi/oiling_roi/slot_layout` 在读取时自动迁移，旧事件文件中的
`logical_part_id` 会映射为 `task_id`。
