# 01 系统架构

## 1. 目标与范围

第一阶段聚焦两个可观察行为：

1. **取料检测**：员工是否从涂油机夹具/取料位取走已完成设备涂油的丝杆。
2. **二次涂油检测**：取料后是否执行了规定的人工二次涂油动作。

不包含：员工离岗、上料数量、设备启停、放料检测、油脂用量/覆盖质量检测。

本版本是“框架版”：模型训练在另一个项目中完成，这里只实现 UI、流程编排、状态机、
事件记录与训练视频采集。

## 3. 线程模型

| 线程 | 创建位置 | 工作内容 | 背压策略 |
| --- | --- | --- | --- |
| Qt 主线程 | Qt | UI 绘制、按钮、定时刷新 | 只读快照 |
| `oilcheck-service` | `OilCheckService.start()` | 按帧率轮询各相机 `FrameBuffer` | 固定节拍 |
| `oilcheck-<station>` | 每工位 `ThreadPoolExecutor(1)` | 检测 + 状态机 | 忙时丢帧，不排队 |
| `training-recorder-<cam>` | `TrainingRecorder.start()` | 编码写 MP4 | 有界队列；满时丢旧帧 |
| 相机 Actor | `hik/session_actor.py` | 串行调用 SDK/PlayCtrl | 消息队列 |

设计意图：

- 状态机与检测器不跨线程并发访问同一工位；单工位单线程即可。
- 解码帧率、检测帧率、UI 帧率、录制帧率彼此独立：UI 慢不影响检测，检测慢时丢帧
  而不是产生越来越大的延迟。
- 事件写盘发生在状态机线程，量小且需要 `fsync`；录制写盘独立线程，避免拖慢流程。

## 4. 启动与关闭

`main.py` 顺序：

1. 解析数据目录（`OILCHECK_DATA_ROOT` 或用户目录），复制默认配置。
2. 初始化日志（文件 + 内存，供日志页）。
3. 创建 `QApplication`。
4. 创建 `HikSdkContext`，但**不立即初始化 SDK**；无相机环境也能进入 UI。
5. 创建 `CameraManager`（只建立会话对象，不连接）。
6. 加载 `oilcheck.json`，创建 `EventStore` 并加载最近 7 天事件。
7. 创建并启动 `OilCheckService`。
8. 创建主窗口并显示。

退出时 `aboutToQuit`：

```text
OilCheckService.shutdown()  停止轮询、停止录制、关闭工位执行器
CameraManager.shutdown()    停止所有相机会话
HikSdkContext.close()       释放 SDK
```

## 5. 一次检测的数据流

```text
相机解码
  └─ FrameBuffer.update_bgr(bgr, w, h, ts)
       └─ OilCheckService 轮询取最新帧（ts 去重）
            ├─ 训练录制 submit(ts, bgr)              [可选]
            └─ 工位执行器
                 ├─ detector.detect(bgr, ts) → FrameDetections
                 └─ StationPipeline.process(detections) → StationSnapshot
                      ├─ 盘体跟踪：TrayTracker 更新 tray 框与 4 个动态 slot ROI
                      ├─ 槽位三态：OCCUPIED / EMPTY / UNKNOWN（时序平滑）
                      ├─ 手部/刷子：ObjectTracker 维护轨迹 ID
                      └─ 取料确认 → 逐根物料操作记录 → 刷子相对运动判定二次涂油
                      ├─ 状态变化
                      └─ EventRecord → EventStore（JSONL）
UI 200ms 读取 StationSnapshot / EventStore.version
```

## 6. 关键设计决策

1. **ROI 使用归一化坐标**：现场标定一次，预览窗口缩放、解码分辨率变化都不影响。
2. **盘体 + 动态槽位**：盘体上下移动时由 `slot_layout` 局部几何自动更新 4 个槽位
   ROI；槽位状态与逐根物料操作记录并行维护，不依赖固定 1~4 号位绝对坐标，也不
   承诺跨遮挡的长期物理身份。
3. **检测与判定分离**：检测器只回答“这一帧有什么”，跨帧证据全部在状态机中，
   便于回放测试和替换模型。
4. **证据不足输出待确认**：遮挡超时、无手部证据的消失、动作幅度不足都进入
   `*_UNCONFIRMED`，不直接判违规。
5. **离开取料区与“被取走”分开**：动态模式下，物料随料盘移出取料区且没有手部交互
   时静默结束 track，不产生取料事件；只有消失前有手部交互才进入取料确认。
6. **默认不伪造事件**：未接入模型时使用 `NullDetector`；演示模式只在 UI 临时切换，
   不写回配置，避免现场误开。

## 7. 与旧项目的关系

旧项目按相机 ID 硬编码检测流程（`app/detectors`、`app/vision`），已归档到 `legacy/`。
新项目保留其相机接入、会话状态机与重连能力，业务层改为“配置驱动的通用工位 + ROI +
时序状态机”，便于一台机器配置多个工位、多个相机。
