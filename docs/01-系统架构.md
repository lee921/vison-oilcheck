# 01 系统架构

对应实现文档第 2、10 节。

## 1. 目标与范围

把相机帧转换为单根丝杆的作业周期，输出「取料完成」与「人工二次涂油完成」
两条事件。视觉 Track ID 只做画面标注与短时关联。

## 2. 分层结构

```text
ui/                    PySide6 页面（监控、复核、录制、设备、设置、日志）
app/oilcheck/service   线程编排：取帧 → 检测 → 状态机 → 事件落盘
app/oilcheck/detector  检测器契约：null / yolo
app/oilcheck/tracker   通用目标跟踪与涂油盘跟踪（ByteTrack 不可用时的回退）
app/oilcheck/bytetrack_adapter  手/刷头的 ByteTrack 适配器
app/oilcheck/association       手-丝杆空间关联、刷头工作点
app/oilcheck/pipeline  取料判定、人工二次涂油判定、作业周期
app/oilcheck/config    oilcheck.json 配置与旧配置迁移
app/oilcheck/events    事件 JSONL 持久化与复核
app/oilcheck/recorder  训练视频分段录制与元数据
app/camera_manager     相机会话、预览、重连
hik/                   海康 HCNetSDK 封装
```

### 模块职责

| 模块 | 输入 | 输出与职责 |
| --- | --- | --- |
| 视频接入 | 相机流 | 解码、时间戳、断流/丢帧监测 |
| ROI 管理 | 原始帧、配置 | 限定有效推理与跟踪范围（涂油盘区 + 工作追踪区） |
| 目标检测 | ROI 图像 | screw / hand / brush / oil_station 位置、角度、关键点 |
| 视觉跟踪 | 逐帧检测 | 手/刷头 ByteTrack 轨迹，容忍短暂漏检 |
| 手-丝杆关联 | 手轨迹、丝杆检测 | 逐帧一对一关联、手持位置推断 |
| 取料判定 | 涂油盘区、手与丝杆 | 空手进盘 → 带料离盘 ⇒ `PICK` |
| 涂油判定 | 手持丝杆、刷头轨迹 | 刷子靠近累计 ≥ `brush_hold_s` ⇒ `MANUAL_OILING` |
| 漏涂判定 | 未完成的 `PICKED` 周期、新取料 | 新取料到来时上一周期仍未涂完 ⇒ `OILING_MISSING` / `NG` |
| 周期与 UI | 事件、时间戳 | 阶段、证据、记录 |

## 3. 线程模型

- 一个轮询线程按配置帧率读取各相机最新帧；
- 每个工位一个单线程执行器执行“检测 + 状态机”，忙时丢帧，避免排队；
- 录制器自带写盘线程；
- 事件写盘在工位线程内完成（量小、需要可靠落盘）；
- UI 只读取快照与事件，不触碰检测线程。

## 4. 启动与关闭

`OilCheckService.start()` 启动轮询线程；每个工位构建检测器与
`StationPipeline`。关闭时停止录制、关闭检测器、释放执行器。

## 5. 一次检测的数据流

```text
Frame(ts, bgr)
  → Detector.detect() → FrameDetections(ts, size, detections)
  → StationPipeline.process()
      1) 区域过滤：只保留涂油盘参考区与工作追踪区内的目标
      2) 跟踪：手/刷头 ByteTrack；涂油盘 oil_station
      3) 取料：空手进盘 → 带料离盘
      4) 涂油：手持丝杆 + 刷子靠近累计
      5) 周期阶段与事件
  → StationSnapshot(tasks, tray, tracks, stats)
  → EventStore.add(EventRecord)
  → UI 轮询快照
```

## 6. 关键设计决策

1. **只有两条判定**：取料（空手进盘、带料离盘）与人工二次涂油（刷子靠近累计）；
   两者的异常出口只有一个漏涂 `NG`（下一次取料打断未涂完的周期），
   不做槽位识别、不做放料判定。
2. **进盘/离盘成对判定**：取料以“同一只手的进盘与离盘”为单位，空手进、
   带料出才成立，避免手从盘边划过或把丝杆放回去被误判。
3. **周期即业务对象**：`task_id` 按取料次数生成，取料与涂油各发一条事件，
   涂油完成即复位。
4. **区域即跟踪范围**：只有中心落在涂油盘区或工作追踪区内的目标才**新建**
   轨迹；已经建立轨迹的目标移出区外后继续跟踪（`roi_track_margin` 内），
   否则手一伸出区就断轨、判定失去目标。
5. **涂油区预留**：`oiling_roi` 本轮只标定与显示，不参与判定。
6. **手/刷用 ByteTrack**：快速小目标靠中心距离代价保持 ID；手持丝杆的位置
   取手附近最近的丝杆检测。

## 7. 与旧项目的关系

旧项目的四槽位、槽位占用、固定取料位逻辑已移除，槽位状态机与刷-手持有关系
在 2.4 一并删除。旧配置中的 `pick_roi/oiling_roi/slot_layout` 在读取时自动迁移，
槽位/遮挡区与废弃判定参数在迁移时清理；旧事件文件中的 `logical_part_id`
会映射为 `task_id`，历史事件类型保留原字符串。
