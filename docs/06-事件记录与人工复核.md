# 06 事件记录与人工复核

对应实现文档第 10、11 节。实现位置：`app/oilcheck/events.py`。

## 1. 事件字段

`EventRecord` 保存到 JSONL，主要字段：

| 字段 | 说明 |
| --- | --- |
| `event_id` | 事件唯一 ID |
| `timestamp_start/end` | 视频时间戳（ISO 本地时间） |
| `station_id` / `camera_id` | 工位与相机 |
| `cycle_id` | 本次运行周期 |
| `task_id` | 业务任务 ID（`TASK-xxxxxx`） |
| `event_type` | `PICK`（取料）/ `MANUAL_OILING`（人工二次涂油）/ `OILING_MISSING`（漏涂 NG） |
| `result` | `CONFIRMED / UNCONFIRMED / NEEDS_REVIEW`（`OILING_MISSING` 固定为 `NEEDS_REVIEW`） |
| `evidence` | 任务 ID、轨迹 ID、盘内停留时长、刷子靠近累计时长、原因码等 |
| `evidence.review_summary` | **通用复核摘要**，见 §1.1。复核页按它渲染详情，不认识任何 SOP 专有键名 |
| `clip_reference` | 事件片段路径（预留） |
| `review_result` / `review_note` | 人工复核结果与备注 |

旧事件文件中的 `logical_part_id` 在读取时映射为 `task_id`；旧类型
（`PUT` / `BRUSH_CONTACT` / `TASK_RESULT`）保留原字符串并标为「（历史）」，
不会被误标成 `PICK`。

### 1.1 通用复核摘要 `review_summary`

判定侧每发一条事件，都在 `evidence` 里放一份结构化的复核摘要。它由
`app/review.py` 定义，**与具体检测项无关**——以后新增别的 SOP 检测，
只要产出同一种结构，复核页一行都不用改。

```json
{
  "check_name": "人工二次涂油",
  "verdict": "漏涂 NG",
  "reason": "取料后 10.40 s 未达到 1.00 s 接触要求（超时）",
  "metrics": [
    {"key": "brush_hold_s", "label": "刷头接触累计", "value": "0.42 s",
     "required": "≥ 1.00 s", "passed": false, "hint": "差 0.58 s"},
    {"key": "brush_min_distance", "label": "刷头离杆最近距离", "value": "0.031",
     "required": "≤ 0.060", "passed": true, "hint": ""}
  ],
  "timeline": [["WAITING_PICK", 1762400000.0], ["PICKED", 1762400003.1],
               ["NG", 1762400013.5]],
  "hints": ["接触时长已达要求的 42%，可能是涂油动作偏快或阈值偏严——建议调出录像人工确认这一件。"]
}
```

| 字段 | 说明 |
| --- | --- |
| `check_name` | 检查项名称，如「人工二次涂油」「取料」 |
| `verdict` | 结论短语，如「漏涂 NG」「涂油完成」 |
| `reason` | 一句判定依据 |
| `metrics[]` | 实测指标：`key`（机器可读）、`label`（中文）、`value`（已格式化）、`required`（要求，可空）、`passed`（`true/false/null`）、`hint`（补充说明） |
| `timeline` | 关键时刻 `[阶段名, 时间戳]`，与周期的 `timeline` 同构 |
| `hints[]` | 复核建议，按条件生成 |

**值为字符串**（`"0.42 s"` / `"88%"` / `"6 帧"`）是刻意的：格式化属于检测项的
口径，复核页只负责按 `passed` 着色，不做单位换算。

漏涂 NG 额外提供的指标（`app/oilcheck/review.py`）：

| `key` | 含义 | 复核时怎么用 |
| --- | --- | --- |
| `brush_hold_s` | 刷头接触累计 / 要求 | 核心：差多少一目了然 |
| `brush_min_distance` | 刷头离杆最近距离 / 接触门限 | 距离远 ⇒ 压根没靠近，或 `brush_point_offset_*` 估偏 |
| `brush_near_frames` | 落入接触邻域的帧数 | `0 帧` ⇒ 本周期刷头从未靠近 |
| `brush_longest_run_s` | 最长**连续**接触 | 远小于累计 ⇒ 断续点几下，不是涂油 |
| `screw_visible_ratio` | 手持丝杆可见比例 | 偏低 ⇒ 接触累计可能被漏检压低 |
| `elapsed_s` | 取料后经过 / 超时阈值 | 只在超时触发时有「要求」 |

旧事件没有这个键：`EventRecord.from_dict` 对 `evidence` 整字典透传，
**JSONL 完全向后兼容**；复核页遇到缺键时回退为原始键值平铺。

```text
<数据目录>/events/events-YYYY-MM-DD.jsonl
<数据目录>/events/reviews-YYYY-MM-DD.jsonl
```

追加写入，不在原文件修改，便于追溯。

## 3. 写入策略

- 内存维护最近事件（默认 5000 条，与监控页可翻页的历史窗口一致）；
- 追加写入后 `flush + fsync`，保证掉电可恢复；
- 启动时加载最近 7 天事件与复核结果；
- 单行损坏只跳过该行，不阻塞启动。

## 4. 内存与 UI 交互

`EventStore.version` 每次变化 +1；监控页/复核页按版本号决定是否刷新，
避免无谓重绘。

## 5. 复核流程

1. 复核页筛选“待复核 / 全部 / 已复核”；
2. 选择事件，下方**详情区**显示：
   - 任务、事件类型、结果（附周期结论 `NG` / `COMPLETED`）；
   - 开始与结束时刻、持续时长（漏涂事件的开始 = 取料时刻，正是「多久没涂」的起点）；
   - 通用复核摘要：结论、实测指标（逐项标 ✓/✗）、复核建议、时间线；
   - 没有摘要的旧事件回退为原始证据键值平铺；
3. 填写备注，提交「确认异常 / 误报 / 无法判断」；已保存的备注会回填到输入框，便于改判；
4. 复核结果异步持久化，并在加载时合并到事件内存。

复核页只认 `review_summary` 的结构，**不出现任何检测项专有键名**——新增 SOP
时不需要改复核页。UI 区分算法结果与人工复核结果；双击监控页事件可跳转复核页。

## 6. 一键清空

“清空事件”只删除 `events-*.jsonl` 与 `reviews-*.jsonl`，训练视频、配置、
日志不受影响。操作不可撤销。

## 7. 数据导出与统计

- `EventStore.counts()` 返回总数、待复核、未确认；
- 可按工位筛选；
- 需要导出时直接使用 JSONL 或按天聚合脚本。

## 8. 维护建议

- 定期归档超过保留期的 JSONL；
- 复核结果应回填为事件级测试标签；
- 训练视频与事件通过 `cycle_id`/时间戳关联；
- 事件片段功能开启后，`clip_reference` 指向本地视频文件。
