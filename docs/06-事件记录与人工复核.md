# 06 事件记录与人工复核

实现文件：`app/oilcheck/events.py`，数据结构在 `app/oilcheck/types.py`。

## 1. 事件字段

对应方案第 8 节：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `event_id` | str | UUID hex，全局唯一 |
| `timestamp_start` | ISO 8601 | 动作起点 |
| `timestamp_end` | ISO 8601 | 确认/结束时刻 |
| `station_id` | str | 工位 |
| `camera_id` | str | 相机 |
| `cycle_id` | str/null | 本次程序运行的周期标识，`RUN-YYYYMMDD-HHMMSS` |
| `logical_part_id` | str | 逻辑物料编号，如 `Part-A`、`Part-B` |
| `slot_index` | int | 来源槽位序号（1~4） |
| `event_type` | str | `PICK` / `MANUAL_OILING` |
| `result` | str | `CONFIRMED` / `UNCONFIRMED` / `NEEDS_REVIEW` |
| `evidence` | object | 规则原因、阈值、时长、幅度、状态前后、检测器等 |
| `clip_reference` | str/null | 事件视频片段；第一版为 null |
| `review_result` | str/null | `CONFIRMED_ABNORMAL` / `FALSE_POSITIVE` / `UNDETERMINABLE` |
| `review_note` | str | 复核备注 |
| `created_at` | ISO 8601 | 入库时间 |

`logical_part_id` 只在取料证据充分时建立；它表示一轮人工操作关联的物料，
不承诺跨遮挡的永久视觉身份。`evidence.operation_id` 关联完整操作记录，
`evidence.source_slot` 标明来源槽位。

## 2. 存储布局

```text
<数据目录>/events/

  reviews-2026-10-22.jsonl   复核记录，按复核日期分文件
```

## 3. 写入策略

- **追加写**：事件与复核都只追加，不就地修改；追溯性更好。
- **每行一条 JSON**（JSONL），UTF-8，`ensure_ascii=False`。
- 每次写入 `flush + os.fsync`，避免断电丢失刚确认的事件。
- 内存只保留最近 `capacity=2000` 条；历史记录仍在文件中。
- 启动时加载最近 7 天的事件与复核，复核结果按 `reviewed_at` 最新者覆盖。
- 损坏的 JSON 行会跳过并记录 warning，不影响后续行。

## 4. 内存与 UI 交互

```python
store.add(event)                    # 状态机线程
store.version                       # 每次变更 +1
store.recent(limit, station_id=...)  # 监控页最近事件
store.pending_review(limit)         # 待复核
store.submit_review(event_id, result, note=...)  # 复核页
```

UI 轮询 `version`，只有变化时才重建表格，避免每秒重绘。

“待复核”指 `result != CONFIRMED` 且尚未填写复核结果的事件；已确认事件默认不进入
待复核列表，但可在“全部”中查看和复核。

## 5. 复核流程

1. 监控页事件列表双击某条事件 → 跳转复核页并选中；
2. 或从“事件复核”页按“待复核/全部/已复核”筛选；
3. 选择事件，填写备注；
4. 点击“确认异常 / 误报 / 无法判断”；
5. 结果追加到 `reviews-*.jsonl`，内存事件立即更新，表格刷新。

复核语义：

| 结果 | 含义 |
| --- | --- |
| 确认异常 | 系统判定的问题确实存在（例如取料未涂油） |
| 误报 | 事件不应发生，或动作不是目标行为 |
| 无法判断 | 证据/画面不足，无法给出结论 |

第一版“打开视频片段”按钮已存在，但事件不保存片段，会提示使用训练录制视频或
现场录像。片段保存的扩展方式见 [07-训练视频录制.md](07-训练视频录制.md) 末尾。

## 6. 一键清空

监控页“最近事件”下方提供“清空事件”按钮：

- 弹出确认框，明确提示会删除本机所有事件与复核记录；
- 确认后清空内存列表，并删除 `events-*.jsonl` 与 `reviews-*.jsonl`；
- **不会删除**训练视频、配置、日志和截图；
- 操作不可撤销，适合调试/演示前重置；正式运行请先备份事件目录。

代码接口：

```python
removed = service.clear_events()   # 返回清空的内存事件数
```

## 7. 数据导出与统计

事件是 JSONL，可直接用 Python/pandas 统计：

```python
import json
from collections import Counter

events = [json.loads(line) for line in open("events-2026-10-22.jsonl", encoding="utf-8")]
print(Counter((e["event_type"], e["result"]) for e in events))
```

建议统计维度：

- 每类事件 CONFIRMED / NEEDS_REVIEW 数量；
- 待确认原因分布（`evidence.reason`）；
- 每工位、每班次事件数；
- 复核结果分布（确认异常/误报/无法判断）；
- 事件延迟：`timestamp_end - timestamp_start`，以及动作实际发生到 UI 显示的延迟
  （需结合现场标注）。

## 8. 维护建议

- 定期备份 `events/`；事件文件按天分片，便于归档。
- 不要手工修改历史 JSONL；如需修正，追加一条复核记录。
- 若调整了逻辑物料编号规则，旧事件仍保留原编号，统计时按 `cycle_id`/时间分段。
- `capacity` 只影响内存与 UI；不影响磁盘记录。
