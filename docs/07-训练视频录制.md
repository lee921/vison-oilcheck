# 07 训练视频录制

实现文件：`app/oilcheck/recorder.py`；UI 页面：`ui/pages/recording_page.py`。

## 1. 目的

第一阶段不训练模型。现场需要持续采集带时间、相机、工位、ROI 信息的原始视频，
交给另一个训练项目做标注与训练。录制器因此只做三件事：

1. 从相机最新帧中按固定帧率取帧；
2. 写成可播放的分段 MP4；
3. 为每段生成 JSON 元数据，并在全局 manifest 中登记。

**录制的是相机原始画面，不叠加 ROI、检测框或状态文字。**

## 2. 存储布局

```text
<数据目录>/recordings/training/
  manifest.jsonl                                 所有分段的追加清单
  <camera_id>/
    2026-10-22/
      cam_6ca47a_20261022_140312.mp4
      cam_6ca47a_20261022_140312.json
      cam_6ca47a_20261022_141312.mp4            # 到达分段时长后自动新建
      cam_6ca47a_20261022_141312.json
```

- 目录由 `recording.training_dir` 决定，可为相对数据目录或绝对路径。
- 文件名使用分段开始时间；重名自动追加序号。
- 分辨率变化会强制切段，避免 VideoWriter 尺寸不匹配。

## 3. 视频参数

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `fps` | 15 | 写入帧率；服务轮询节拍会至少达到该帧率 |
| `segment_seconds` | 300 | 分段时长；过短会产生大量小文件 |
| `codec` | `mp4v` | OpenCV FourCC；`mp4v` 兼容性最好 |
| `auto_start` | false | 启动服务后自动为每个工位相机开始录制 |

实际写入帧率受相机解码帧率、服务轮询和写盘能力限制。队列满时会丢帧，并在状态和
元数据中计数；不会为了录制而阻塞检测。

## 4. 运行机制

```text
OilCheckService 轮询线程
  └─ recorder.submit(ts, bgr)
       └─ 有界队列（约 3 秒帧数）
            └─ recorder 线程
                 ├─ cv2.VideoWriter.write(frame)
                 ├─ 达到 segment_seconds 或分辨率变化 → 结束当前段
                 ├─ 写同名 .json 元数据
                 └─ 追加 manifest.jsonl
```

- `submit()` 非阻塞；队列满时丢弃最旧帧，保留最新画面。
- 录制线程与检测线程独立；编码慢不会拖慢状态机。
- 分段开始时立即写一份 `status: recording` 的元数据；结束时更新为 `finished`
  并补全结束时间、帧数、丢帧数。异常退出时至少保留初始元数据。

## 5. 元数据字段

同名 `.json`：

```json
{
  "type": "training_video",
  "status": "finished",
  "path": "/data/recordings/training/cam_6ca47a/2026-10-22/cam_6ca47a_20261022_140312.mp4",
  "camera_id": "cam_6ca47a",
  "camera_name": "1号位",
  "station_id": "ST01",
  "station_name": "1号取料工位",
  "started_at": "2026-10-22T14:03:12.100+08:00",
  "ended_at": "2026-10-22T14:08:12.100+08:00",
  "started_at_epoch": 1761112992.1,
  "ended_at_epoch": 1761113292.1,
  "fps": 15,
  "width": 1920,
  "height": 1080,
  "frame_count": 4500,
  "dropped_frames": 3,
  "codec": "mp4v",
  "rois": {
    "pick_roi": {"kind": "rect", "points": [[0.28, 0.08], [0.72, 0.42]]},
    "tray_roi": {"kind": "rect", "points": [[0.28, 0.08], [0.72, 0.42]]},
    "oiling_roi": {"kind": "rect", "points": [[0.10, 0.50], [0.48, 0.96]]},
    "slot_layout": [
      {"index": 1, "name": "1号槽", "x1": 0.02, "y1": 0.15, "x2": 0.23, "y2": 0.9}
    ],
    "slots": []
  }
}
```

训练项目可直接用 `rois` 做裁剪，或在标注工具中叠加 ROI。`tray_roi` 是盘体搜索区，
`slot_layout` 是相对盘体框的 4 个槽位局部几何；旧 `slots` 字段仅用于兼容。

## 6. 操作方式

### UI

- 训练录制页采用左右分栏：
  - 左侧：默认实时画面；点击“开始录制”会自动启动相机预览（若尚未启动），
    等相机进入预览状态后再开始写盘；
  - 右侧：已录制分段列表，双击某段在左侧播放；
  - 左侧“实时画面”按钮可从录像回放切回实时；
  - 顶部“预览/停止预览”按钮可单独启动或停止相机预览，不启动录制；
- 监控页只显示录制状态（如“录制中 mm:ss · N帧”），不提供录制开关；
- “打开录制目录”打开文件管理器；“刷新分段”读取最新元数据；
- 双击分段行在左侧播放该 MP4；播放结束后保留最后一帧，双击或“实时画面”可重新开始/返回实时；
- 每行左侧有勾选框，可勾选多个；支持“全选”，点击“删除勾选”：
  - 二次确认后删除 MP4、同名 JSON 元数据，并同步清理 `manifest.jsonl` 中的对应条目；
  - 正在录制的分段会被跳过并提示；
  - 若正在回放被删除的视频，会先停止回放再删除（Windows 文件句柄要求）；
  - 删除不可撤销。

### 配置自动录制

```json
"recording": {
  "auto_start": true,
  "training_dir": "recordings/training",
  "fps": 15,
  "segment_seconds": 300
}
```

服务启动后为每个启用的工位相机自动开始录制。多相机时请评估磁盘与编码压力。

### 代码

```python
status = service.start_training_recording("cam_6ca47a")
service.recording_status("cam_6ca47a")
service.stop_training_recording("cam_6ca47a")
segments = service.recording_segments(limit=100)
```

## 7. 磁盘估算

粗略估算（实际取决于画面复杂度与编码器）：

```text
每小时大小 ≈ 码率(Mbps) × 3600 / 8
```

以 1080p、15 fps、`mp4v` 中等画质约 4–8 Mbps 计，每小时约 1.8–3.6 GB。
建议：

- 按班次归档，定期清理已标注数据；
- 不要把录制目录放在系统盘；
- 分段时长不要过短（建议 5–15 分钟）；
- 磁盘不足时主动停止录制并在 UI/日志报错。

## 8. 排障

| 现象 | 原因/处理 |
| --- | --- |
| 录制中但帧数不增长 | 相机未处于预览状态；先“开始采集” |
| `无法创建视频文件` | OpenCV 缺少编码器；换 `codec`（如 `XVID`、`avc1`）或安装带 FFmpeg 的 OpenCV |
| 视频时长比实际短 | 丢帧较多；降低录制帧率/分辨率，或提升磁盘写入 |
| 分段 JSON 只有 `recording` 状态 | 程序异常退出；视频仍可播放，用 manifest/文件名恢复时间 |
| 训练视频带检测框 | 不应发生；确认没有把预览截图当录制源 |

## 9. 后续：事件前后视频片段

方案要求复核时能打开异常前后片段。当前版本保留了 `clip_reference` 字段但未实现。
推荐扩展：

1. 服务层为每个相机维护 `pre_seconds` 环形帧缓冲；
2. 状态机发出 `NEEDS_REVIEW` 事件时，创建片段任务：
   - 写入事件前 N 秒缓存帧；
   - 继续写入事件后 M 秒帧；
   - 结束后更新事件的 `clip_reference`；
3. 复核页“打开视频片段”即可直接用系统播放器打开。

注意片段写盘与训练录制共用磁盘和编码资源，建议单独配置码率与保留周期。
