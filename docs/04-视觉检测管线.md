# 04 视觉检测管线

对应实现文档第 3~7 节。实现位置：`app/oilcheck/detector.py`、
`app/oilcheck/tracker.py`、`app/oilcheck/pipeline.py`。

## 1. 职责边界

检测器只回答“这一帧有什么”，跟踪器维持短时视觉身份，`StationPipeline`
负责跨帧的取料与涂油判定。本模块不依赖 Qt、相机 SDK 或具体推理框架。

## 2. 检测结果契约

```python
FrameDetections(ts, frame_size, detections)
Detection(label, confidence, box, track_id=None, angle=None, point=None)
```

- `angle`：OBB 长轴角度（弧度），没有时由框长边估计；
- `point`：关键点，刷头工作端优先使用；
- `track_id`：检测器可不填，由跟踪器分配。

## 3. 检测类别

类别名与训练导出权重严格一致（`best.pt` 实际输出 4 类）：

| id | 类别 | 标注对象 | 用途 |
| --- | --- | --- | --- |
| 0 | `hand` | 每只手（左右统一） | 进盘/离盘与持有判定 |
| 1 | `brush` | 刷具（含工作端） | 刷头靠近判定 |
| 2 | `oil_station` | 涂油工位/盘体 | 涂油盘区随动 |
| 3 | `screw` | 每根独立丝杆 | 手持对象 |

配置里通过 `hand_label` / `brush_label` / `tray_label` / `screw_label`
指定这四个名字，UI 与流水线都不硬编码字符串。

## 3.1 推理尺寸

`detector.imgsz=0` 时自适应：读权重 checkpoint 里训练用的 `imgsz`（当前为
1024），读不到回退 640。显式配置非 0 值时按 stride（32）向上取整。
解析结果会写进快照的 `stats["imgsz"]`，监控页状态条上直接可见。

## 3.2 raw_mode：旁路 SOP

默认 `raw_mode=false`，走完整 SOP 判定。**只有显式设为 `true`** 时才进入
旁路模式（现场排查用），此时 `StationPipeline.process()` 走直通分支：

- 不做区域过滤；
- 不建轨迹、不判取料、不判涂油；
- 不产生任何事件，也不写事件库；
- `snapshot.detections` 就是模型这一帧的全部输出，另附
  `stats["label_counts"]` 按类别计数。

用途是先确认“模型能不能把画面里所有标签都检测出来”。排查完把
`raw_mode` 改回 `false` 即恢复完整 SOP 判定。注意旧配置升级时该字段默认补
`false`，不会因为迁移而停留在旁路模式。

## 4. ROI 与工作追踪区

工位有三个区域：

| 区域 | 用途 | 运行方式 |
| --- | --- | --- |
| `tray_roi` | 涂油盘区底区 | 手工区覆盖盘体下方手臂活动范围，与模型检出的 `oil_station` 框取并集，跟随盘体上下移动 |
| `work_roi` | 工作追踪区 | 跟踪与判定的有效范围 |
| `oiling_roi` | 涂油区 | 本轮只做标定与显示，预留给后续涂油范围约束 |

每帧先做区域过滤：

1. 检测框中心落在 `work_roi` 或涂油盘区内 → 保留；
2. 其余（画面边缘、机身、物料盒等区域外的目标）→ 丢弃，不建轨迹；
3. `oil_station` 检测不参与过滤，只用于更新涂油盘区。

## 5. 跟踪与关联

三层职责严格分开：

| 层 | 对象 | 实现 |
| --- | --- | --- |
| 视觉跟踪 | 手、刷头 | `ByteTrackObjectTracker`（`bytetrack_adapter.py`） |
| 行为关联 | 手↔丝杆 | `HandScrewAssociator`（`association.py`） |
| 位置推断 | 手持丝杆 | 手附近最近的丝杆检测（`held_infer_distance`） |

### 5.1 手与刷头：ByteTrack

ultralytics 自带的 `BYTETracker` 只按 IoU 关联，20×20 的小目标每帧移动 120px
时第 2 帧起就丢 ID。适配器子类化并改写 `get_dists`：

```text
类别不一致                     → 代价 1.0
中心距离 > max_center_distance → 代价 1.5（高于任何阈值 ⇒ 不匹配）
否则 cost = α·(1-IoU) + (1-α)·(中心距离 / max_center_distance)
```

- 不用 `min(iou, distance)`：那会让一个指标的优秀表现完全抵消另一个指标的异常；
- 手与刷头分别用 `id_base=100000 / 200000` 命名空间，ID 不会互相覆盖；
- 第二阶段（低置信度补救）同样走这套加权代价；ultralytics 原生这里是硬编码
  纯 IoU，小目标快速移动时必然失配；
- 卡尔曼状态用 `XYWH`（手/刷框近似方形，XYAH 的长宽比会把框宽拉回）；
- 视觉 ID 宣布丢失后不会被 ByteTrack 内部的 `lost_stracks` 复活；名额满时
  先淘汰漏检最久的轨迹，而不是直接拒绝新目标；
- 判定（进盘/离盘、握持、锚点交叠）用本帧**原始检测框**，显示用平滑后的
  滤波框——快速移动时滤波框会滞后一帧；
- ultralytics 导入失败或配置 `*_tracker_backend=object` 时回退到原 `ObjectTracker`。

### 5.1.1 检测置信度与第二阶段

`detector.confidence` 必须低于 `bytetrack_high_thresh`（当前 0.25 < 0.45），
否则低分框在检测层就被丢掉，第二阶段永远收不到输入。低分框只能维持已有
轨迹，不能新建（受 `bytetrack_new_thresh` 约束）。

`bytetrack_high_thresh` 从 0.30 提到 0.45 是按示例视频**截图逐帧走查**定下来的：

- 手框在「只框手掌」与「手掌+前臂」之间来回跳，相邻帧面积比 p99 到 1.6~1.9、
  最大 9.7 倍，中心被拖 0.10~0.14 画面对角线，而手的真实帧间位移中位数只有
  0.003；同一 ID 一帧跳 0.29 对角线的那次，是真刷子还在手里、轨迹却被
  画面左上角的**白毛巾误检**接走了；另一段视频里同样的现象来自**白色导轨**。
- 这些误检框的置信度普遍偏低。把第一阶段门槛提到 0.45 后，两段视频的
  刷头「大跳变」（同一 ID 相邻帧位移 >10% 对角线）从 2 次 / 1 次降到 0 / 0，
  手部指标与 PICK / MANUAL_OILING / OILING_MISSING 计数完全不变。
- 需要对比时用 `uv run python tools/tracker_ab.py --high-thresh 0.30,0.45`。

**刷头出生准入**（`brush_spawn_max_distance`，默认 0 关闭）：刷子干活时必然在
手边或丝杆边，远离两者的「刷头」基本都是白色物件误检。开启后只把这些检测
的分数压到 `bytetrack_new_thresh` 以下——阻止新建轨迹，已有轨迹仍能靠第二
阶段接回。示例③（091519）上刷头 ID 6→3、`matched` 0.667→0.826；但示例①
反而多 1 个 ID，收益不普适，所以默认关闭，等现场视频再定。

### 5.1.2 当前跟踪层的已知边界

- **手框定义不稳定**是检测/标注口径问题，不是关联算法问题：同一只手在
  「手掌」与「手掌+前臂」之间跳会让中心跟着跳。已在会话中逐一验证过
  OC-SORT、C-BIoU、NSA Kalman、两档门限、方向一致性项、按真实帧间隔预测、
  尺寸相对门限、观测中心关联、中值滤波、墓碑重连等改法，全部无效或更差
  （OC-SORT 的 ID 数下降是靠 OCR 的纯 IoU 把轨迹接到另一只手上换来的）。
  只能在训练侧统一标注口径，或用 OBB 角度/关键点约束。
- 业务口径（每个作业周期绑定过的 ID 数）：三段示例视频里**每件的手部 ID
  都是 1**；刷头在示例②③ 也都是 1，只有示例① 的 `TASK-000001` 在 f294 换过
  一次刷头 ID（当时接触累计才 0.13s，`brush_hold_s` 为 1.0s，换 ID 只是把
  累计重新起算，不影响结论）。画面里 5~6 只手/手臂是别的工位与边缘误检，
  不影响判定——涂油累计走的是丝杆锚点，不依赖手部 ID。

### 5.2 手-丝杆关联

用空间距离 + 交互关系（IoU / 包含）判定这一帧哪只手在操作哪根丝杆，多手多杆时
用匈牙利全局分配，并带 UNMATCHED 选项——宁可不关联，也不为凑满分配强行配对。
关联逐帧重算，不做跨帧锁定：现场只需要知道“此刻手是否拿着丝杆”，
跨帧身份由作业周期维护。

## 6. 取料判定

一句话：**空手进盘、带料离盘**。

**所有子判定都用最近 n 个采样点投票，不拿单帧当结论**
（`pick_sample_every_frames` / `pick_history_samples`）：

| 子判定 | 判据 | 为什么 |
| --- | --- | --- |
| 手是否在盘内 | 窗口内任一样本在盘内 → 确认进过盘；窗口多数在盘外 → 确认离盘 | 盘区边线附近手框中心会抖一帧，单帧越界会劈开一段取料 |
| 离盘时手里有没有杆 | 攒满 n 个盘外采样 → 多数投票；点数不足就得定论 → 见过一帧手握杆即算 | 手握杆时杆被遮、置信度掉到 0.5 左右；只看离盘当帧必漏 |
| 进盘时手里有没有杆 | 盘外观测历史投票（盘外帧才入历史） | 手伸进盘当帧必与静置杆交叠，当帧判定永远是「持有」 |

「手里有没有杆」的几何判据（`_holding_screw`）有三条，满足任一即算握着：

1. **杆心落在手框内**，或两者 IoU ≥ 0.15；
2. **杆框与手框右上角区域相交**（右边 50%、上边 50% 那一块），且杆至少
   30% 的面积落在这块区域里。实际握姿是拳头攥住杆身、杆从虎口（右上角）
   伸出去，此时杆心已经在手框外。丝杆又细又长，面积只有手框的 17~26%，
   而 IoU 的结构上限就是面积比——0.15 这条门限在握持状态下几乎不可达
   （示例③握持段实测 IoU 只有 0.03~0.13）。
3. 第 2 条只在**手位于涂油盘区外**时启用，且**落在盘内的杆不算**——那是
   盘里的静置杆。手伸到盘边挑料时，盘里那排静止杆正好落在手框右上区里，
   不排除会被判成「带料进盘/离盘」，整件取料丢掉或凭空多出一件。

**进盘定性还要再剔除一次盘内的杆**（`_record_outside_holding`）。盘外握持
历史只回答「这一趟是空手进来还是带着料进来」，而手要经过盘边时，手框
（实测 348×399 px，接近盘宽）必然把盘里那排静置杆框进去，它们的**中心**
就落在手框内，命中第 1 条基础判据。一条这样的观测进了历史，本次进盘就被
判成「带料进盘」，整件取料丢掉——示例② 第 95 帧附近的取料即如此。

这里只剔除进盘定性用的历史、不动 `_holding_screw` 本身：离盘后的握持采样
仍要认盘内的杆，因为取料瞬间手里那根杆往往还压在盘区上方，那正是这一件
料被带走的证据（视频② f463 那次取料的前两个采样点就落在盘区内，提前剔除
会把整件取料判丢）。

点数不足时不能一律按「空手」处理：那样一次真实取料连作业周期都建不出来，
后面的涂油判定就无从谈起（现场表现为「取料没跑完就停了」）。采样按 k 帧
一个点，手离盘后很快就出画面时窗口一个点都攒不到——为此离盘后逐帧记录
「见过手握杆」的正向证据，不挑采样点；手在盘外直接消失（连离盘都没来得及
按窗口确认）时，按最后观测到的手框与握持状态结算。

逐只手维护一段「进盘—离盘」过程（`_HandVisit`）：

1. 手中心进入涂油盘区的那一帧，记录 `holding_on_entry`——此刻手里是否已有丝杆
   （`hand_screw_max_distance` 内最近的丝杆检测）；
2. 手中心离开涂油盘区的那一帧：
   - `holding_on_entry` 为真（带料进盘又带料离盘）→ 不判取料；
   - 离盘时手里没有丝杆（空手离开）→ 不判取料；
   - 空手进盘、带料离盘 → 且盘内停留 ≥ `pick_confirm_s` → 发
     `PICK/CONFIRMED`，周期进入 `PICKED`；
3. 手部轨迹消失超过 `holding_lost_timeout_s`，该进盘过程作废。

不要求进入涂油区；只要离开涂油盘时手里有丝杆就算取料完成。

## 7. 人工二次涂油判定

1. 存在 `PICKED` 状态的周期时，用**丝杆锚点跟踪**定位手里那根杆：
   - 优先取「与**本周期那只手**的框交叠」的丝杆检测（别的工人/另一只手
     握的杆不算）；
   - 手上没有交叠杆时，按位置连续性取离锚点最近的杆；这条分支只在锚点
     仍贴近「最后一次确认握持」的位置时有效（`hand_screw_max_distance`），
     否则锚点会在密集的静置丝杆之间逐帧漂走；
   - 锚点是位置而非视觉 ID，因此不受手部 ID Switch 影响；
2. 刷头工作点（Keypoint 优先，否则按 `brush_point_offset_*` 从框内推算）
   到丝杆中心的归一化距离 ≤ `brush_contact_distance` → 视为本帧靠近；
3. 靠近帧按 `dt` 累加 `brush_hold_s`；未靠近的帧不累计（也不清零）。
   `dt` 与漏检桥接空档都受「单帧可信间隔」约束（约为已建立节拍的 2 倍），
   掉帧、跳帧不会把累计时长凭空放大；时间不可信的帧写入
   `stats["timing_reliable"]=false`；
4. 累计 ≥ `brush_hold_s` → 发 `MANUAL_OILING/CONFIRMED`，周期置 `OILED` 并结束，
   回到等待下一次取料。

刷子只短暂靠近、接触距离不够、或没有取料周期时都不产生事件。

## 8. 作业周期

一个周期只有三个阶段与两条事件：

```text
WAITING_PICK ──PICK/CONFIRMED──> PICKED ──MANUAL_OILING/CONFIRMED──> OILED
       ▲                                                              │
       └──────────────────────── 周期结束并复位 ──────────────────────┘
```

- `TaskResult` 为 `PROCESSING` / `COMPLETED` / `NG`（漏涂）；
- 不产生 `TASK_RESULT` / `PUT` / `BRUSH_CONTACT`；除漏涂 `NG` 外不做分级；
- 新取料到来时若上一周期仍停在 `PICKED`，上一周期判 `NG` 并发
  `OILING_MISSING`，新取料另起周期（不复用，否则 `PICK` 事件会被去重吞掉）；
- 周期结束后**按条数**保留最近 `completed_keep_count` 条（默认 4，与监控页任务卡片格数一致），更早的才回收。不按时间清：按时间清会让卡片栏在每件做完后空掉，现场看不到刚才那几件的结论。
- 另有一道**时间兜底**：`completed_retain_s`（默认 3600 秒）之后也回收，防止内存随运行时长无限增长。两者取交集——任一条件满足就回收。
- 进行中的周期永远不在这里回收。

## 9. 服务层调度

`OilCheckService` 每工位单线程执行检测+状态机，忙时丢帧；录制与事件写盘独立。
UI 通过 `StationSnapshot` 读取任务、跟踪、检测、统计。

## 10. 接入外部训练模型

### 10.1 模型要求

- 输出类别名与配置一致（当前为 `hand` / `brush` / `oil_station` / `screw`）；
- 普通 Detect 输出即可，OBB 与关键点为可选项（有则用，无则按框推算）；
- 按完整视频/日期/批次划分数据集。

### 10.2 启用步骤

```json
"detector": {
  "kind": "yolo",
  "model_path": "model/detect/exp/weights/best.pt",
  "confidence": 0.5,
  "imgsz": 0,
  "device": "cpu",
  "raw_mode": false
}
```

`uv sync` 安装推理依赖后重启服务。`imgsz=0` 自动使用训练尺寸；
日志里会打印实际类别与尺寸，便于核对权重是否配对。

### 10.3 离线回放

`tools/detect_video.py` 直接对示例视频跑推理，不需要相机与 UI：

```bash
uv run python tools/detect_video.py
uv run python tools/detect_video.py --video some.mp4 --limit 120
```

输出带框视频与逐帧 JSONL 到 `data/detect_preview/`。
单元测试则可直接构造 `FrameDetections` 喂给 `StationPipeline`。

## 11. 性能建议

- 只对涂油盘区与工作追踪区内的目标**新建**轨迹；已建立轨迹的目标移到区外后
继续跟踪，但区外目标不会新建轨迹；
- 隔帧推理时考虑轨迹预测误差；
- 刷头是小目标，必要时提高 ROI 分辨率或改用关键点；
- 记录推理耗时、丢帧率、待确认比例。

## 12. 明确不做的事

- 不识别槽位、不绑定槽位；
- 不判发放料事件；只判漏涂 `NG`，不做其他分级；
- 不判断机器自动涂油质量；
- 不通过单目画面证明周向覆盖或油脂附着量。
