# 04 视觉检测管线

对应实现文档第 3~7 节。实现位置：`app/oilcheck/detector.py`、
`app/oilcheck/tracker.py`、`app/oilcheck/pipeline.py`。

## 1. 职责边界

检测器只回答“这一帧有什么”，跟踪器维持短时视觉身份，`StationPipeline`
负责跨帧证据、业务身份和状态判定。本模块不依赖 Qt、相机 SDK 或具体推理框架。

## 2. 检测结果契约

```python
FrameDetections(ts, frame_size, detections)
Detection(label, confidence, box, track_id=None, angle=None, point=None)
```

- `angle`：OBB 长轴角度（弧度），没有时由框长边估计；
- `point`：关键点，刷头工作端优先使用；
- `track_id`：检测器可不填，由跟踪器分配。

## 3. 检测类别

类别名与训练导出权重严格一致（`best.pt` 实际输出 4 类）：

| id | 类别 | 标注对象 | 用途 |
| --- | --- | --- | --- |
| 0 | `hand` | 每只手（左右统一） | 取料交互、遮挡、共同运动 |
| 1 | `brush` | 刷具（含工作端） | 接触与相对运动 |
| 2 | `oil_station` | 涂油工位/盘体 | 取料参考区域随动 |
| 3 | `screw` | 每根独立丝杆 | 取料、手持、刷涂对象 |

配置里通过 `hand_label` / `brush_label` / `tray_label` / `screw_label`
指定这四个名字，UI 与流水线都不硬编码字符串。

## 3.1 推理尺寸

`detector.imgsz=0` 时自适应：读权重 checkpoint 里训练用的 `imgsz`（当前为
1024），读不到回退 640。显式配置非 0 值时按 stride（32）向上取整。
解析结果会写进快照的 `stats["imgsz"]`，监控页状态条上直接可见。

## 3.2 raw_mode：旁路 SOP

`detector.raw_mode=true` 时 `StationPipeline.process()` 走直通分支：

- 不做 ROI / 排除区过滤；
- 不建轨迹、不判取料、不判刷涂；
- 不产生任何事件，也不写事件库；
- `snapshot.detections` 就是模型这一帧的全部输出，另附
  `stats["label_counts"]` 按类别计数。

用途是先确认“模型能不能把画面里所有标签都检测出来”。确认无误后把
`raw_mode` 设为 `false` 即恢复完整 SOP 判定。

## 4. ROI 与排除区

每帧先做 ROI 过滤：

1. 检测框中心落在任一 `exclude_rois` → 丢弃（物料盒完全不参与推理）；
2. 检测框中心不在 `tray_roi ∪ hand_roi ∪ brush_roi` → 丢弃；
3. 涂油盘检测不受 ROI 过滤，用于随动定位。

涂油盘参考区域：优先使用检测到的 `oil_tray` 预测框；没有检测或不可靠时回退
配置的 `tray_roi`。不恢复四个槽位。

## 5. 短时跟踪

丝杆、手、刷头共用一个贪心匹配跟踪器：

- 预测位置 + 中心距离匹配，IoU 高时给予小幅优势；
- 短时漏检保留 `*_track_max_missing_s`；
- 新轨迹需连续命中 `*_track_min_hits` 次；
- 保存 OBB 角度与关键点，随轨迹更新。

视觉 Track ID 可以变化；业务任务 ID 在取料确认后独立维护。

## 6. 取料事件证据

| 证据 | 实现 |
| --- | --- |
| 取料前存在 | 丝杆在 `tray_roi` 内被跟踪，记录 `was_in_tray` |
| 手部交互 | 手中心与丝杆中心距离 ≤ `pick_hand_distance` |
| 共同运动 | 手和丝杆位移均超过 `pick_motion_min`，方向余弦 ≥ 0.5，且相对位置变化 ≤ `pick_relative_max`，累计 ≥ `pick_comotion_min_s` |
| 离开区域 | 丝杆中心离开涂油盘参考区域，进入 `hand_roi` |
| 持续关联 | 进入手持区后保持关联 ≥ `pick_confirm_s` |
| 遮挡处理 | 离盘后丝杆不可见、手仍在手持区，超过 `pick_occlusion_timeout_s` → 待确认 |
| 多候选 | 同一只手存在距离接近的多个候选 → 不强制选最近，转待确认 |

只有以上组合证据成立才创建 `PICK CONFIRMED`；手单独经过不会产生事件。

## 7. 手持丝杆与业务身份

- 候选阶段建立 `TASK-xxxxxx`（`pick_status=CANDIDATE`），确认后升级；
- 每帧按 `screw_track_id` 更新丝杆框与主轴；
- Track 丢失时按“上一位置 + 手部附近”在未认领的丝杆轨迹中重关联；
- 重关联唯一 → `TRACK_REASSOCIATED`；不唯一/无候选 → `identity_status=UNCERTAIN`；
- 超过 `holding_lost_timeout_s` → `holding_status=LOST`，暂停累计刷涂证据，
  任务保留等待恢复；手和丝杆都离开后才给出终态。

## 8. 刷涂行为

1. 取当前任务的丝杆框与主轴（OBB 角度，或框长边）；
2. 刷头工作点：Keypoint 优先，否则按 `brush_point_offset_*` 从框内推算；
3. 计算工作点到丝杆轴向线段的距离，≤ `brush_contact_distance` 视为接触；
4. 将工作点投影到丝杆局部坐标：
   - 轴向坐标归一化到 `[-1, 1]`；
   - 按 `coverage_segments` 映射区段并标记已覆盖；
   - 累计相邻帧 `|Δ轴向| / 丝杆长度` 作为相对运动；
5. 接触 + 有效运动 + 覆盖比例达到 `coverage_required`、累计时长达到
   `brush_min_duration_s` → `OILING_COMPLETED`；
6. 刷头静止、刷杆只经过不接触、接触但无相对运动，都不累计完成进度。

## 9. 服务层调度

`OilCheckService` 每工位单线程执行检测+状态机，忙时丢帧；录制与事件写盘独立。
UI 通过 `StationSnapshot` 读取任务、跟踪、检测、统计。

## 10. 接入外部训练模型

### 10.1 模型要求

- 输出类别名与配置一致（当前为 `hand` / `brush` / `oil_station` / `screw`）；
- 普通 Detect 输出即可，OBB 与关键点为可选项（有则用，无则按框推算）；
- 按完整视频/日期/批次划分数据集。

### 10.2 启用步骤

```json
"detector": {
  "kind": "yolo",
  "model_path": "model/detect/exp/weights/best.pt",
  "confidence": 0.5,
  "imgsz": 0,
  "device": "cpu",
  "raw_mode": false
}
```

`uv sync` 安装推理依赖后重启服务。`imgsz=0` 自动使用训练尺寸；
日志里会打印实际类别与尺寸，便于核对权重是否配对。

### 10.3 离线回放

`tools/detect_video.py` 直接对示例视频跑推理，不需要相机与 UI：

```bash
uv run python tools/detect_video.py
uv run python tools/detect_video.py --video some.mp4 --limit 120
```

输出带框视频与逐帧 JSONL 到 `data/detect_preview/`。
单元测试则可直接构造 `FrameDetections` 喂给 `StationPipeline`。

## 11. 性能建议

- 只对有效 ROI 推理，物料盒区域裁剪；
- 隔帧推理时考虑轨迹预测误差；
- 刷头是小目标，必要时提高 ROI 分辨率或改用关键点；
- 记录推理耗时、丢帧率、待确认比例。

## 12. 明确不做的事

- 不识别槽位、不绑定槽位；
- 不判断机器自动涂油质量；
- 不通过单目画面证明周向覆盖或油脂附着量。
