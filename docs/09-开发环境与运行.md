# 09 开发环境与运行

## 1. 环境要求

| 项 | 要求 |
| --- | --- |
| Python | 3.11 ~ 3.13（仓库 `.python-version` 为 3.12） |
| 包管理 | [uv](https://docs.astral.sh/uv/) |
| 系统 | Windows / Linux；GUI 需要桌面环境 |
| 相机 | 海康设备与对应 HCNetSDK/PlayCtrl 动态库（可选，无相机也能进 UI） |

## 2. 安装

```bash
uv sync
```

会创建 `.venv` 并安装：

- `pyside6`、`pyside6-fluent-widgets`：桌面 UI；
- `opencv-python`：视频解码/编码、截图；
- `numpy`、`pillow`；
- `torch` / `torchvision`（CUDA 12.8 构建）+ `ultralytics`：模型推理；
- 开发组：`pytest`、`black`、`ruff`。

### 2.1 运行环境以 GPU 服务器为准

**`pyproject.toml` 与 `uv.lock` 统一锁定 CUDA 版本**（`pytorch-cu128` 索引，
即 `torch==2.11.0+cu128`）。部署服务器应当具备 NVIDIA 显卡与匹配的驱动。

```bash
nvidia-smi                                   # 确认驱动可用
uv run python -c "import torch; print(torch.cuda.is_available())"
```

输出 `True` 表示推理会走 GPU。检测器默认 `device` 为 `cpu`，
服务器上应把 `config/oilcheck.json` 的 `detector.device` 改为 `cuda:0`（或 `0`）。

### 2.2 无 GPU 的本地开发机

**不要为了本机没有显卡去改 `pyproject.toml` 或 `uv.lock`。** 仓库的依赖解析
以部署服务器为准，改成本地 CPU 索引会让两边产生分叉，服务器上还得再改回来。

CUDA 版 torch 在没有显卡的机器上**可以正常安装和运行**，只是推理自动走 CPU、
速度慢一些。所以直接 `uv sync` 即可，代价只是多占约 4GB 磁盘（nvidia 运行库）。

想确认跑了哪条路径，看启动日志里检测器打印的那行：

```
检测模型已加载: ...（imgsz=1024, device=cpu, half=False, 类别=0=hand,...）
```

`device` 由配置 `detector.device` 决定，默认 `auto`：有 CUDA 选 `cuda:0`，
没有就退到 `cpu`。

如果确实要省这 4GB（且接受与 lock 不一致），可以在 `uv sync` 之后把 torch
换成本地 CPU 版：

```bash
uv pip install --index-url https://download.pytorch.org/whl/cpu \
    --reinstall torch torchvision
```

之后任何一次 `uv sync` 都会把它恢复成 lock 里的 CUDA 版本，属于预期行为。

## 3. 运行

```bash
uv run python main.py
```

默认全屏显示。首次运行会在 `~/OilCheckData` 生成配置、日志、事件、录制目录。

开发时建议：

```bash
OILCHECK_DATA_ROOT=$(pwd) uv run python main.py
```

Windows PowerShell：

```powershell
$env:OILCHECK_DATA_ROOT = (Get-Location); uv run python main.py
```

这样 `config/`、`logs/`、`events/`、`recordings/` 都在仓库目录，便于查看与清理。

## 4. 数据目录

默认根目录：`~/OilCheckData`（Windows：`%USERPROFILE%\OilCheckData`）。

```text
<数据目录>/
  config/app.json
  config/cameras.json
  config/oilcheck.json
  logs/app-YYYY-MM-DD.log
  logs/hik_sdk/
  snapshots/
  events/events-YYYY-MM-DD.jsonl
  events/reviews-YYYY-MM-DD.jsonl
  recordings/training/...
```

重置运行配置：停止程序后删除 `<数据目录>/config/`，下次启动会从仓库模板复制。
注意这会丢失现场标定，操作前先备份。

## 5. 测试与代码检查

```bash
uv run pytest
uv run ruff check .
uv run black --check .
```

格式化：

```bash
uv run black .
```

### 网络较慢时

首次安装需要下载 PySide6 等大包。若官方源速度过慢，可临时指定镜像（不改项目配置）：

```bash
UV_DEFAULT_INDEX=https://mirrors.aliyun.com/pypi/simple uv sync
```

安装完成后 `uv.lock` 已固定版本，后续可正常使用 `uv sync`。

## 6. 无相机/无显示环境

- 无相机：可以启动 UI、编辑配置、回放示例视频；点击“开始采集”才会加载 SDK。
- 无显示（服务器/CI）：Qt 无法创建窗口，单元测试不需要 Qt，可直接
  `uv run pytest`。如需冒烟启动可用 `QT_QPA_PLATFORM=offscreen`。
- 海康 SDK 缺失：启动 UI 不受影响；开始采集时报错并写入日志。

## 7. Linux 注意事项

- `lib/linux` 已包含海康 SDK 动态库；若系统缺少依赖（如 `libcrypto.so.1.1`），
  仓库提供了软链接示例，正式部署请按设备厂商文档安装。
- 相机 SDK 为 64 位时，Python 也必须是 64 位。
- Wayland 下无边框/全屏行为可能与 X11 不同；现场工控机建议 X11。

## 8. Windows 注意事项

- 动态库目录由 `HikSdkContext` 自动加入 `os.add_dll_directory`。
- 路径包含中文时，配置与日志使用 UTF-8 读写；录制文件名使用 ASCII 相机 ID +
  时间戳，避免编码问题。
- 打包为 exe 时需把 `lib/win`、`config/`、`resources` 一并分发；当前未提供
  PyInstaller 脚本。

## 9. 常见启动问题

| 现象 | 处理 |
| --- | --- |
| `ModuleNotFoundError: PySide6` | 没有在 uv 环境中运行；使用 `uv run python main.py` |
| `Could not load the Qt platform plugin "xcb"` | 安装系统 Qt 依赖或设置 `QT_QPA_PLATFORM`；无显示环境不要启动 UI |
| 界面全屏无法退出 | 现场按 Esc 不会退出；开发时按 Ctrl+C 或修改 `win.showFullScreen()` 为 `show()` |
| 配置改了没生效 | 程序读的是数据目录副本；检查 `OILCHECK_DATA_ROOT` |
| 中文显示方块 | 系统缺少中文字体；安装 Noto CJK / 微软雅黑 |
| 录制视频无法播放 | 换 `codec` 或安装带 FFmpeg 的 OpenCV |
