# 10 测试与验证

## 1. 单元测试

```bash
uv sync
uv run pytest
```

| 文件 | 覆盖内容 |
| --- | --- |
| `tests/test_pipeline.py` | 槽位三态时序、盘体移动不误跳变、取料确认、槽位无手部证据不建操作、遮挡待确认后补确认、刷子相对运动确认/证据不足待确认、多槽位并行、模拟检测器全流程、槽位几何与配置往返 |
| `tests/test_pipeline_dynamic.py` | 盘体上下移动时槽位状态稳定、`TrayTracker` 漏检/重关联、手部轨迹短时丢失 |
| `tests/test_tracker.py` | 旧 `RodTracker` 连续移动、短时漏检、移出区域、多目标独立跟踪 |
| `tests/test_frame_buffer.py` | 停止预览后缓存帧清除 |
| `tests/test_events.py` | 事件追加写、重载、复核持久化、筛选与计数 |
| `tests/test_recorder.py` | 训练视频分段、元数据、manifest、未启动时不写入、删除分段与 manifest 清理 |
| `tests/test_config.py` | 仓库模板合法性、默认 tray 模式、fixed 模式槽位校验、非法 ROI |

测试不依赖 Qt、相机 SDK 或真实模型；状态机通过构造 `FrameDetections` 回放。

### 当前测试的边界

- 只验证规则逻辑与文件行为，**不验证真实视觉可行性**。
- 模拟检测器测试只证明“契约与流程可跑通”，不代表现场识别率。
- 录制测试在 OpenCV 缺少 `mp4v` 编码器时会 skip。

## 2. 演示模式手工验证

无相机/无模型时，用演示模式走通整个链路：

1. `uv run python main.py`；
2. 监控页选择工位；
3. 打开“演示模式”：
   - 无相机时会自动生成合成演示画面（顶部显示“演示（无相机）”），
     该画面只驱动流程，**不会写入训练录制**；
   - 有相机时直接使用真实画面；
   - 当前默认配置为 tray 模式：画面显示上下移动的机器涂油盘、4 个槽位、手部/
     刷子轨迹与丝杆检测；
   - 槽位面板显示 `OCCUPIED / EMPTY / UNKNOWN`；示例脚本按周期取走 1 个槽位并
     执行刷子涂油，其他槽位保持有料；
   - 人工操作卡片显示 `Part-A` 等逻辑编号；
   - 观察操作状态变化：`PICKED → OILING_CANDIDATE → OILING_CONFIRMED`；
   - 观察遮挡阶段是否进入 `PENDING_CONFIRMATION`；
   - 观察事件列表出现 `PICK` / `MANUAL_OILING`；
4. 打开“事件复核”：
   - 双击事件跳转；
   - 对待确认事件标注“误报/无法判断/确认异常”；
   - 刷新后复核结果保留；
5. 打开“训练录制”：
   - 开始录制，确认帧数增长；
   - 停止后分段表出现视频，双击可播放；
   - 检查同名 JSON 元数据；
6. 设置页修改阈值并保存，确认服务重载、状态不再沿用旧参数（会重建状态机）。

> 演示模式的事件仅用于流程联调，验收统计时必须排除 `detector=simulated` 的记录。

## 3. 离线回放验证

推荐用训练录制页采集现场视频，再离线回放：

```python
import cv2
from app.oilcheck.config import OilCheckConfig
from app.oilcheck.detector import create_detector
from app.oilcheck.pipeline import StationPipeline
from app.oilcheck.types import EventRecord

station = OilCheckConfig.from_dict(...).stations[0]
detector = create_detector(station)          # 真实模型接入后为 yolo
events: list[EventRecord] = []
pipeline = StationPipeline(
    station=station,
    pipeline_cfg=cfg.pipeline,
    on_event=events.append,
    cycle_id="REPLAY",
    detector_name=detector.name,
)

cap = cv2.VideoCapture("recording.mp4")
fps = cap.get(cv2.CAP_PROP_FPS) or 15
ts = 0.0
while True:
    ok, frame = cap.read()
    if not ok:
        break
    ts += 1.0 / fps
    pipeline.process(detections=detector.detect(frame, ts))

for e in events:
    print(e.to_dict())
```

要点：

- 时间戳用视频帧序号/帧率，不要用 `time.time()`，否则阈值行为不对；
- 人工标注真实事件区间，与回放输出按时间匹配；
- 分别统计取料和二次涂油，不要合并；
- 先调阈值，再上现场实时试运行。

## 4. 现场数据采集建议

按方案 P0：

- 覆盖正常取料、提前取料、4 根交错、手部遮挡、调整位置、短暂停留、二次涂油、
  普通拿取、空位等场景；
- 每个班次/光照条件至少若干分钟连续视频；
- 记录相机位置、镜头、分辨率、节拍；
- 人工标注事件起止时间、位置、结果、是否遮挡；
- 标注规范统一后再统计，避免“取料”定义不一致。

## 5. 验收指标

分别对取料与二次涂油统计：

| 指标 | 计算 |
| --- | --- |
| 召回率 | 系统确认的真事件 / 人工标注真事件 |
| 准确率 | 系统确认事件中真事件的比例 |
| 待确认比例 | 进入 `NEEDS_REVIEW` 的事件 / 人工标注事件（或系统事件） |
| 事件延迟 | 动作实际结束到 UI 显示确认结果的时间 |
| 误报原因分布 | 按 `evidence.reason` 统计 |

注意：

- 不能用目标检测 mAP 代替流程指标；
- 待确认不是“错”，但要单独报告，因为它意味着人工介入成本；
- 目标值需业务方根据漏检风险、误报处置成本、现场节拍共同确定。

- [ ] 事件 JSONL 字段完整、可重载；
- [ ] 相机断开/恢复不影响 UI 与录制状态；
- [ ] 配置保存后阈值立即生效；
- [ ] 日志无异常堆栈。
