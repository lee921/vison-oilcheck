### 当前测试的边界

- 只验证规则逻辑与文件行为，**不验证真实视觉可行性**。
- 模拟检测器测试只证明“契约与流程可跑通”，不代表现场识别率。
- 录制测试在 OpenCV 缺少 `mp4v` 编码器时会 skip。

## 2. 示例视频与模型检测手工验证

用真实录像验证“模型能否检测出画面里所有标签”：

1. `uv run python main.py`；
2. 监控页选择工位；
3. “画面源”下拉选择任一示例（`示例① 105708` ~ `示例5 092817`）；
   - 画面来自 `data/sample_video` 下的 mp4，检测由 `best.pt` 完成；
   - 顶部状态条显示 `检测：xx.x ms · imgsz 1024 · N目标（hand x / brush x /
     oil_station x / screw x）`；
   - 画面上的框覆盖模型输出的全部类别；
   - 状态条信息行显示 `示例回放 名称 · 进度%`；
   - 示例回放**不写入训练录制**；
4. 把 `detector.raw_mode` 设为 `false` 后重启，即恢复取料/涂油判定，
   观察任务阶段变化：`WAITING_PICK → PICKED → OILED`，
   事件列表里应只出现「取料」与「人工二次涂油」两类事件，每个周期各一条；
   出现「人工二次涂油未完成」说明该件被下一件打断，属于预期外的漏涂。

离线批量核对（不经 UI）：

```bash
uv run python tools/detect_video.py            # 跑配置里的全部示例视频
uv run python tools/detect_video.py --limit 120
```

跟踪质量核对（对比阈值/策略，看事件是否变化、手与刷头 ID 稳不稳）：

```bash
uv run python tools/tracker_ab.py --high-thresh 0.30,0.45
uv run python tools/tracker_ab.py --brush-spawn 0.10
uv run python tools/tracker_ab.py --downsample 3      # 模拟低帧率
```

重点看 `big`（同一 ID 相邻帧位移 >10% 画面对角线的次数）：它比 `ids` 更能
反映「ID 悄悄换了目标」。行尾 `!` 表示事件数与基线不同，`hijack?` 表示
大跳变变多。

输出 `data/detect_preview/<名字>.mp4`（带框）与 `.jsonl`（逐帧检测），
终端打印每类总数与平均置信度。

**逐件清点两个工序**（不建作业周期、两工序互不依赖）：

```bash
uv run python tools/detect_operations.py                  # 配置里的全部示例视频
uv run python tools/detect_operations.py --no-annotate    # 只要结论
uv run python tools/detect_operations.py --save-contacts  # JSON 里附全部接触片段
```

它回答的是「这段录像里到底取了几次料、刷了几次」，与监控页的作业周期
不是同一把尺子——这里**不要求取料与涂油配对**，也不要求先后顺序：

- 视频开始时已经在手里刷的丝杆（取料发生在录制之前）也能判出涂油；
- 只取料没涂油、只涂油没取料，都各自如实报出来；
- 涂油以**杆**为界切分：刷头贴着同一根手持杆累计接触 ≥ `brush_hold_s`
  算一次；换一根杆即另起一次（见脚本内 `OilingDetector` 的说明）。

输出 `data/operations_preview/<名字>.json`（`picks` / `oilings` 两个清单，
含起止时间、帧号、接触时长、杆心位置）与同名 `.mp4`（带框，`PICK`/`OIL`
进度显示在左上角）。示例视频的参考结果：

| 视频 | 取料 | 人工二次涂油 |
| --- | --- | --- |
| 示例① 105708 | 4 | 4 |
| 示例② 140911 | 4 | 4 |
| 示例③ 091519 | 2 | 3 |
| 示例④ 094439 | 3 | 4 |
| 示例5 092817 | 3 | 3 |
| 示例6 153539 | 4 | 4 |
| 示例7 170216 | 3 | 4 |

与监控页的差异来自两处，都是预期内的：

- **录像开头那一件**：示例③ 从 0.07s 就在刷、示例④ 从 0.73s 就在刷、
  示例7 从 0.07s 就在刷，取料发生在录制开始之前；监控页按作业周期判，
  只能看到取料之后的涂油；
- **示例5 第 2 件**（5.93s）：监控页把它判成「盘内停留 2.80s 的取料」，
  实际是工人把手伸进盘里按住夹具、顺手把杆停在盘区下沿刷，
  这里判为一次取料 + 一次涂油，不复用作业周期的结论。

示例7 还有两处是「目视核对过、确实该这么判」的：

- 13.7~14.6s 手把杆放到盘边、空手离开，**不是**取料（杆没被带走）；
- 19.3s 之后刷手还在动，但手里已经没有杆（模型也检不到丝杆），
  后面的接触不累计。

逐条回看（打开窗口播放，并标出每一次动作）：

```bash
uv run python tools/play_operations.py                 # 依次播放全部已出结果的视频
uv run python tools/play_operations.py --video 6       # 只看第 6 段（1 基）
uv run python tools/play_operations.py --speed 0.5     # 半速
uv run python tools/play_operations.py --video 6 --snapshot 10.4   # 只存一张核对图
```

画面左侧实时显示当前正在发生的动作（取料闪黄框、涂油显示接触时长），
右侧是这段录像的**全部**动作时间线：`✓` 已发生、`▶` 正在发生、`·` 还没到。
按键：空格暂停、`[` / `]` 跳到上/下一次动作、`r` 重播、`Esc` 退出。
读的就是 `detect_operations.py` 的 JSON，所以判定改了重跑检测即可，
播放器不用改。`--snapshot` 可以在没有图形界面的机器上导出核对图。

## 3. 离线回放验证

推荐用训练录制页采集现场视频，再离线回放：

```python
import cv2
from app.oilcheck.config import OilCheckConfig
from app.oilcheck.detector import create_detector
from app.oilcheck.pipeline import StationPipeline
from app.oilcheck.types import EventRecord

station = OilCheckConfig.from_dict(...).stations[0]
detector = create_detector(station)          # 真实模型接入后为 yolo
events: list[EventRecord] = []
pipeline = StationPipeline(
    station=station,
    pipeline_cfg=cfg.pipeline,
    on_event=events.append,
    cycle_id="REPLAY",
    detector_name=detector.name,
)

cap = cv2.VideoCapture("recording.mp4")
fps = cap.get(cv2.CAP_PROP_FPS) or 15
ts = 0.0
while True:
    ok, frame = cap.read()
    if not ok:
        break
    ts += 1.0 / fps
    pipeline.process(detections=detector.detect(frame, ts))

for e in events:
    print(e.to_dict())
```

要点：

- 时间戳用视频帧序号/帧率，不要用 `time.time()`，否则阈值行为不对；
- 人工标注真实事件区间，与回放输出按时间匹配；
- 分别统计取料和人工二次涂油，不要合并；
- 正常生产只出现 `PICK` 与 `MANUAL_OILING`；出现 `OILING_MISSING` 说明该件
  取走后没刷够就被下一件打断，需要现场核对；
- 先调阈值，再上现场实时试运行。

## 4. 现场数据采集建议

按方案 P0：

- 覆盖正常取料、提前取料、4 根交错、手部遮挡、调整位置、短暂停留、二次涂油、
  普通拿取、空位等场景；
- 每个班次/光照条件至少若干分钟连续视频；
- 记录相机位置、镜头、分辨率、节拍；
- 人工标注事件起止时间、位置、结果、是否遮挡；
- 标注规范统一后再统计，避免“取料”定义不一致。

## 5. 验收指标

分别对取料与二次涂油统计：

| 指标 | 计算 |
| --- | --- |
| 召回率 | 系统确认的真事件 / 人工标注真事件 |
| 准确率 | 系统确认事件中真事件的比例 |
| 待确认比例 | 进入 `NEEDS_REVIEW` 的事件 / 人工标注事件（或系统事件） |
| 事件延迟 | 动作实际结束到 UI 显示确认结果的时间 |
| 误报原因分布 | 按 `evidence.reason` 统计 |

注意：

- 不能用目标检测 mAP 代替流程指标；
- 待确认不是“错”，但要单独报告，因为它意味着人工介入成本；
- 目标值需业务方根据漏检风险、误报处置成本、现场节拍共同确定。

## 6. 回归检查清单

每次修改状态机/检测器/配置后：

- [ ] `uv run pytest` 全绿；
- [ ] 示例回放能看到四个类别的检测框；
- [ ] `raw_mode=false` 时走通「取料 → 人工二次涂油完成」一个完整周期；
- [ ] 录制能生成可播放 MP4 与元数据；
- [ ] 事件 JSONL 字段完整、可重载；
- [ ] 相机断开/恢复不影响 UI 与录制状态；
- [ ] 配置保存后阈值立即生效；
- [ ] 日志无异常堆栈。
