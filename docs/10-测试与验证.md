```bash

```

| `tests/test_recorder.py` | 训练视频分段、元数据、manifest、未启动时不写入、删除分段与 manifest 清理 |
| `tests/test_config.py` | 仓库模板合法性、旧配置迁移、排除 ROI、非法 ROI |

测试不依赖 Qt、相机 SDK 或真实模型；状态机通过构造 `FrameDetections` 回放。

### 当前测试的边界

- 只验证规则逻辑与文件行为，**不验证真实视觉可行性**。
- 模拟检测器测试只证明“契约与流程可跑通”，不代表现场识别率。
- 录制测试在 OpenCV 缺少 `mp4v` 编码器时会 skip。

## 2. 示例视频与模型检测手工验证

用真实录像验证“模型能否检测出画面里所有标签”：

1. `uv run python main.py`；
2. 监控页选择工位；
3. “画面源”下拉选择 `示例① 105708` 或 `示例② 140911`；
   - 画面来自 `data/sample_video` 下的 mp4，检测由 `best.pt` 完成；
   - 顶部状态条显示 `检测：xx.x ms · imgsz 1024 · N目标（hand x / brush x /
     oil_station x / screw x）`；
   - 画面上的框覆盖模型输出的全部类别；
   - 状态条信息行显示 `示例回放 名称 · 进度%`；
   - 示例回放**不写入训练录制**；
4. 把 `detector.raw_mode` 设为 `false` 后重启，即恢复取料/刷涂 SOP 判定，
   观察任务阶段变化：
   `PICK_CANDIDATE → LEAVING_TRAY → PICK_CONFIRMED → HOLDING →
    BRUSH_CONTACT → BRUSHING → OILING_COMPLETED`。

离线批量核对（不经 UI）：

```bash
uv run python tools/detect_video.py            # 跑配置里的全部示例视频
uv run python tools/detect_video.py --limit 120
```

输出 `data/detect_preview/<名字>.mp4`（带框）与 `.jsonl`（逐帧检测），
终端打印每类总数与平均置信度。

## 3. 离线回放验证

推荐用训练录制页采集现场视频，再离线回放：

```python
import cv2
from app.oilcheck.config import OilCheckConfig
from app.oilcheck.detector import create_detector
from app.oilcheck.pipeline import StationPipeline
from app.oilcheck.types import EventRecord

station = OilCheckConfig.from_dict(...).stations[0]
detector = create_detector(station)          # 真实模型接入后为 yolo
events: list[EventRecord] = []
pipeline = StationPipeline(
    station=station,
    pipeline_cfg=cfg.pipeline,
    on_event=events.append,
    cycle_id="REPLAY",
    detector_name=detector.name,
)

cap = cv2.VideoCapture("recording.mp4")
fps = cap.get(cv2.CAP_PROP_FPS) or 15
ts = 0.0
while True:
    ok, frame = cap.read()
    if not ok:
        break
    ts += 1.0 / fps
    pipeline.process(detections=detector.detect(frame, ts))

for e in events:
    print(e.to_dict())
```

要点：

- 时间戳用视频帧序号/帧率，不要用 `time.time()`，否则阈值行为不对；
- 人工标注真实事件区间，与回放输出按时间匹配；
- 分别统计取料和二次涂油，不要合并；
- 先调阈值，再上现场实时试运行。

## 4. 现场数据采集建议

按方案 P0：

- 覆盖正常取料、提前取料、4 根交错、手部遮挡、调整位置、短暂停留、二次涂油、
  普通拿取、空位等场景；
- 每个班次/光照条件至少若干分钟连续视频；
- 记录相机位置、镜头、分辨率、节拍；
- 人工标注事件起止时间、位置、结果、是否遮挡；
- 标注规范统一后再统计，避免“取料”定义不一致。

## 5. 验收指标

分别对取料与二次涂油统计：

| 指标 | 计算 |
| --- | --- |
| 召回率 | 系统确认的真事件 / 人工标注真事件 |
| 准确率 | 系统确认事件中真事件的比例 |
| 待确认比例 | 进入 `NEEDS_REVIEW` 的事件 / 人工标注事件（或系统事件） |
| 事件延迟 | 动作实际结束到 UI 显示确认结果的时间 |
| 误报原因分布 | 按 `evidence.reason` 统计 |

注意：

- 不能用目标检测 mAP 代替流程指标；
- 待确认不是“错”，但要单独报告，因为它意味着人工介入成本；
- 目标值需业务方根据漏检风险、误报处置成本、现场节拍共同确定。

- [ ] `raw_mode=false` 时走通取料、涂油、待确认、复核；
- [ ] 录制能生成可播放 MP4 与元数据；
- [ ] 事件 JSONL 字段完整、可重载；
- [ ] 相机断开/恢复不影响 UI 与录制状态；
- [ ] 配置保存后阈值立即生效；
- [ ] 日志无异常堆栈。
