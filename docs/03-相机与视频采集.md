# 03 相机与视频采集

## 1. 实现位置

| 文件 | 作用 |
| --- | --- |
| `hik/sdk_context.py` | 加载 HCNetSDK/PlayCtrl，管理初始化/清理与动态库目录 |
| `hik/session_actor.py` | 用 Actor 线程串行执行所有 SDK 调用，避免跨线程并发 |
| `hik/state_machine.py` | 会话状态：断开/连接/已连接/预览/停止/错误 |
| `hik/decode.py` | `FrameBuffer`：保存最新一帧 BGR 与时间戳 |
| `hik/session.py` | 对外会话门面：连接、预览、停止、截图、帧缓存 |
| `app/camera_manager.py` | 多相机会话管理、启动/停止、重连、健康检查 |

## 2. 启动流程

用户点击“开始”后：

```text
CameraManager.start_async(camera_id)
  └─ 线程池执行 _start_worker
       ├─ HikSdkContext.initialize()       首次调用时加载动态库
       ├─ HikSession.start_preview()
       │    └─ SessionActor 串行执行连接、预览、回调注册
       └─ 重置重连退避
```

主程序启动时**不会**初始化 SDK，因此：

- 没有安装海康 SDK 或没有相机时，仍可进入 UI、编辑配置、使用演示模式。
- 第一次点击“开始”才会暴露动态库缺失等问题，错误会写入日志页。

## 3. 预览模式

| 模式 | 条件 | 帧数据 | 适用 |
| --- | --- | --- | --- |
| `decode` | `preferred_mode=decode` 或没有有效 HWND | PlayCtrl 解码为 BGR，写入 `FrameBuffer` | **本项目推荐**：检测、录制、截图都需要 BGR |
| `direct` | `preferred_mode=direct` 且传入 HWND | SDK 直接渲染到窗口，业务层无帧 | 仅预览；不适用于本流程 |

监控页启动相机时不传 HWND，因此即使配置为 `direct`，也会回退到 `decode`。

## 4. 帧缓冲与消费者

```python
session = manager.get_session(camera_id)
frame = session.frame_buffer.get()   # Frame(bgr, width, height, ts)
```

- `FrameBuffer` 只保留**最新**一帧，旧帧自动丢弃。
- `ts` 是解码线程写入时的 `time.time()`，服务层用它去重。
- BGR 数组每帧新建，不会被后续帧原地覆盖；消费者可安全读取。
- 解码帧率由 `app.json` 的 `decode_max_fps` 控制，服务层再按 `pipeline.max_fps`
  和录制帧率取帧。因此实际检测帧率 = min(解码帧率, 服务轮询帧率)。

消费者：

1. `OilCheckService` 轮询线程：分发给状态机与录制器。
2. 监控页：直接读取最新帧用于显示（不经过服务队列，保证画面实时）。

## 5. 截图

监控页“截图”调用 `HikSession.snapshot(path)`：

- 优先使用 PlayCtrl 抓图（JPEG/BMP）；
- 失败时回退为当前 `FrameBuffer` 的 BGR 写图；
- 默认保存到 `<数据目录>/snapshots/<camera_id>_<时间戳>.bmp`。

截图可用于 ROI 标定，见 [02-配置说明.md](02-配置说明.md)。

## 6. 重连与离线

`CameraManager.tick()` 每秒由 UI 定时器调用，交给 `ReconnectSupervisor` 判断：

- 相机状态、最近活动时间、错误信息、配置的 `max_backoff_s`；
- 超时或异常时执行停止/重连；
- 重连成功会重置退避。

注意：

- 相机断开期间 `FrameBuffer` 保留最后一帧；服务层用 `frame.ts` 去重，不会重复处理。
- 监控页在线状态要求：会话状态为 `previewing` 且最近帧在 5 秒内。
- 录制器在相机未预览时仍可启动，但不会写入帧；UI 会提示。

## 7. 多相机/多工位

- `cameras.json` 可以有多个相机；`oilcheck.json` 的每个 station 通过 `camera_id`
  绑定一个相机。
- 一个相机可以绑定多个工位（不推荐，ROI 会竞争同一帧）；通常一个工位一个相机。
- `OilCheckService` 为每个启用的 station 建立独立执行器，不同工位互不阻塞。

## 8. 排障

| 现象 | 排查 |
| --- | --- |
| 点击开始报 SDK 动态库缺失 | 检查 `lib/linux` 或 `lib/win` 是否存在 `libhcnetsdk.so` / `HCNetSDK.dll`、`PlayCtrl` |
| 登录失败 | 检查 IP/端口/用户名/密码；密码可用 `env:VAR` |
| 预览中但画面不动 | 查看 `decode_max_fps`、相机码流、日志中的解码错误 |
| 检测/录制没有帧 | 确认使用 `decode` 模式；确认相机状态为“预览中” |
| 离线后不自动恢复 | 检查 `reconnect.enable`、`max_backoff_s`、网络与设备状态 |
| Linux 下 PlayCtrl 崩溃 | 确认使用与系统架构匹配的 SDK 动态库；查看 `logs/hik_sdk` |

## 9. 后续可扩展点

- RTSP/文件视频输入：实现一个与 `HikSession` 相同的最小接口（`state`、
  `frame_buffer`、`snapshot`）即可复用服务层。
- 多路解码限流：当前按相机独立限帧，若 CPU 不足可统一调度。
- 硬件加速解码：在 `hik/session_actor.py` 的解码路径替换实现。
