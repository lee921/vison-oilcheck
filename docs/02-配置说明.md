# 02 配置说明

对应实现文档第 3、10 节。ROI 与阈值都应版本化，并支持现场快速调整。

## 1. 配置放在哪里

**配置只有一份：仓库根下的 `config/`。** UI 里改的值、判定实际读的值、仓库里
的文件始终是同一个文件，不存在副本。

| 文件 | 位置 | 内容 |
| --- | --- | --- |
| 应用参数 | `config/app.json` | 布局、帧率、日志/截图目录、中继 |
| 相机 | `config/cameras.json` | 相机列表与重连参数 |
| 检测 | `config/oilcheck.json` | ROI、判定阈值、模型、示例视频清单 |

运行数据（日志、事件、截图、训练录制）不在这里，仍写在数据目录
`~/OilCheckData/`（Windows：`%USERPROFILE%\OilCheckData`），可用
`OILCHECK_DATA_ROOT` 覆盖。配置目录可用 `OILCHECK_CONFIG_ROOT` 覆盖，
主要用于测试与离线工具。

因为配置在仓库里，`git pull` 不会覆盖它（工作区有未提交改动时会提示冲突），
现场标定可以直接提交入库，跟着代码一起分发到别的机器。

**改完配置不需要重启程序**：服务按文件修改时间轮询，`config/oilcheck.json`
被外部改动（手工编辑、编辑器保存、UI 保存、另一个进程写入）后会重新加载并
重建工位运行时。文件解析失败时保留上一次的配置继续运行，不会让所有工位一起
消失。

**在哪里确认程序读的是哪个文件**：把鼠标移到设置页的「打开 ROI 标定」按钮上，
提示里会列出生效配置的绝对路径与修改时间。

## 3. cameras.json

海康设备信息：`id/name/enabled/ip/port/username/password/channel/stream_type/
preferred_mode/reconnect`。密码支持 `env:VAR_NAME`，推荐把密码放在环境变量
`OILCHECK_CAM_PASSWORD` 中，避免明文入库。

```json
"password": "env:OILCHECK_CAM_PASSWORD"
```

## 4. oilcheck.json

### 4.1 顶层

```jsonc
{
  // 配置结构版本，供自动迁移判断，不要手工改
  "version": "2.6",
  // 时序判定参数。单位：时间=秒，距离=按画面对角线归一化
  "pipeline": { ... },
  "recording": { ... },
  "demo": { ... },
  // 工位列表，每个工位一台相机
  "stations": [ ... ]
}
```

**配置文件支持注释**（JSONC）。仓库模板里每个参数上方都有一行说明，
程序读写时都会正确处理 `//` 与 `/* */`；在 UI 里改参数再保存，
注释不会丢失（注释表在 `app/oilcheck/config.py` 的 `CONFIG_COMMENTS`）。

新增配置项时记得在 `CONFIG_COMMENTS` 里补一行，
`tests/test_config.py::test_comment_table_covers_every_config_key` 会检查漏写。

### 4.1.1 版本升级与自动迁移

配置就是仓库里的 `config/oilcheck.json`，没有“模板副本”这回事。旧版本的
配置结构由下面的迁移逻辑在启动时升级，现场调好的 ROI 不会被覆盖。

程序启动时会按 `version` 做一次幂等迁移，并在最后把**文件里缺的键**按当前
代码默认值补写回去（只补不删、不改已有值），所以文件里的键集合始终等于实际
生效的参数集合——对着配置文件排查时不会出现「参数看着还是老的、实际已按新
默认值在跑」：

- 旧版本（`< 2.1`）会补齐新字段、把 `detector.kind=null` 改为 `yolo`、
  填入仓库权重路径；
- `demo` 段整段缺失、或段在但缺 `videos` 键时，按模板补回示例视频清单
  （以前这类文件会被补成空的 `videos: []`，下拉里一条示例都没有且不报错）；
- 升到 `2.6` 时，旧版本遗留的空清单也补回模板，之后**显式**写成
  `"videos": []` 则保持为空——那是主动清空，下拉里只剩“实时相机”是预期行为；
  启动日志会打印一条“示例视频清单为空”的警告，附实际配置路径；
- 旧版本（`< 2.2`）会把工位 ROI 收敛为 `tray_roi` + `work_roi`：旧手持区/刷涂区
  取包围矩形作为工作追踪区，并删除手持区、刷涂区、排除区字段；
- 旧版本（`< 2.4`）会删除已废弃的槽位/遮挡区字段（`slot_rois`、`occlusion_rois`、
  `slot_auto_count`、`slot_follow_tray`）与不再生效的判定参数（`slot_*`、
  `brush_hand_*`、`coverage_*`、`association_sustain_s` 等），并给每个工位补
  `oiling_roi`（缺省沿用 `work_roi`）；旧 `brush_min_duration_s` /
  `oiling_min_duration_s` 会映射为 `brush_hold_s`；现场已调过的 ROI 与阈值一律保留；
- 旧类别名 `oil_tray` / `brush_head` / `rod` 会改成模型实际输出的
  `oil_station` / `brush` / `screw`（1.0 配置里的 `rod_label` 字段先并成
  `screw_label`，再把值纠正过来）。这一项**不看版本号**：旧值可能已经跟着
  配置一路升级、版本号是新的但值还是旧名，按版本判断会永远漏掉。只纠正
  旧默认名，现场自己改过的类别名一律保留；
- 已有的 ROI、阈值、相机配置一律保留；
- 代码里有默认值、文件里缺的键会补写回文件（值即实际生效的默认值）；
- 当前版本不认识的键只记一条警告，原样保留不删除；
- 写回时按模板的键顺序重排，`diff` 运行配置与仓库模板只剩值差异；
- 改动前把原文件备份为 `oilcheck.json.bak`。

所以服务器拉取新代码后**不需要手工改配置**。若想回到出厂配置：
`git checkout config/oilcheck.json`，或删掉后从 `git show` 取回。

### 4.2 pipeline：取料判定

| 字段 | 默认 | 含义 |
| --- | --- | --- |
| `max_fps` | 15 | 检测最大帧率 |
| `pick_hand_distance` | 0.05 | 手-丝杆接近判定距离（按画面对角线归一化） |
| `pick_confirm_s` | 0.30 | 手在盘内的最短停留时长；低于该值视为从盘边划过，不判取料 |
| `pick_sample_every_frames` | 2 | 取料判定的采样间隔（帧）：每隔这么多帧记一次「在不在盘内 / 手里有没有杆」 |
| `pick_history_samples` | 3 | 取料判定保留的采样点数：用最近这么多个采样点投票，单帧抖动不影响结论。与上一项相乘决定离盘后攒够多少个盘外采样才定论 |
| `hand_screw_max_distance` | 0.10 | 手-丝杆关联的最大归一化中心距离 |
| `hand_interaction_margin` | 0.02 | 手框交互判定扩张量 |
| `holding_lost_timeout_s` | 2.0 | 手部轨迹消失后，进盘过程作废的时长 |

### 4.3 pipeline：跟踪

| 字段 | 默认 | 含义 |
| --- | --- | --- |
| `hand_track_*` | 0.15 / 0.8 / 1 | 手部跟踪 |
| `hand_track_max_active` | 8 | 手部轨迹同时保留上限（漏检轨迹仍占名额，设小了新手框建不了轨迹） |
| `brush_track_max_active` | 4 | 刷头轨迹同时保留上限 |
| `brush_track_*` | 0.15 / 0.8 / 1 | 刷头跟踪 |
| `tray_max_distance` / `tray_max_missing_s` / `tray_min_confidence` | 0.2 / 1.0 / 0.3 | 涂油盘定位 |
| `hand_tracker_backend` / `brush_tracker_backend` | auto | `auto` / `bytetrack` / `object` |
| `bytetrack_high_thresh` 等 | 见模板 | ByteTrack 相关阈值（需现场标定） |
| `screw_anchor_max_step_abs` | 0.08 | 锚点单帧位移绝对上限；盘里丝杆间距 0.02~0.03，低帧率下靠它防跳杆 |
| `bytetrack_buffer_s` | 2.00 | 丢失轨迹保留时长（秒），运行时按帧率折算 |
| `bytetrack_cost_alpha` | 0.40 | IoU 与中心距离代价的加权 |
| `bytetrack_match_thresh` | 1.00 | 关联代价阈值。未进门限的代价固定 1.5，故 1.0 表示只看距离/IoU 门限 |

### 4.4 pipeline：二次涂油与任务

| 字段 | 默认 | 含义 |
| --- | --- | --- |
| `brush_contact_distance` | 0.06 | 刷头工作端到丝杆中心的接触距离（归一化） |
| `brush_hold_s` | 1.0 | 刷子靠近累计到该时长即判「人工二次涂油完成」 |
| `held_infer_distance` | 0.10 | 手持丝杆位置推断的最大手-杆距离 |
| `held_predict_hold_s` | 0.50 | 手相对偏移预测的保持时长 |
| `screw_anchor_max_step` | 0.12 | 丝杆锚点单帧最大位移（实测手持杆 p90=0.081，取 0.12 覆盖约 p95） |
| `screw_anchor_hold_s` | 0.50 | 锚点当帧找不到时，按锚点位置继续跟踪的时长 |
| `brush_hold_max_gap_s` | 0.50 | 刷子整帧漏检时，允许补回的最大空档 |
| `frame_scale_max` | 4.0 | 帧率自适应倍率上限 |
| `roi_track_margin` | 0.20 | 目标移出工作追踪区后继续跟踪的距离余量 |

> 帧率自适应：上表中的距离/时长门限，以及手/刷头/涂油盘跟踪器的中心距离门限，
> 都会按 `帧间隔 / (1/max_fps)` 放大（上限 `frame_scale_max`）。`pick_confirm_s`、
> `brush_hold_s` 这类纯时间阈值不缩放。
| `single_active_task` | true | 单活动任务模式 |
| `task_max_active` | 4 | 最大同时任务数 |
| `completed_retain_s` | 10.0 | 完成后在 UI 保留时长 |

旧版字段 `brush_part_distance`、`brush_min_duration_s`、`oiling_min_duration_s`
会在读取时自动映射到新字段，无需手工改现场配置。已删除的槽位、刷-手关联、
覆盖度量等参数会在迁移时从配置文件中清理。

### 4.5 recording：录制

同旧版：`training_dir`、`fps`、`segment_seconds`、`codec`、`auto_start`、
`event_clips_enabled`。

### 4.6 stations：工位

```json
{
  "station_id": "ST01",
  "name": "1号取料工位",
  "camera_id": "cam_6ca47a",
  "enabled": true,
  "tray_roi": {"kind": "rect", "points": [[0.28, 0.08], [0.72, 0.42]]},
  "work_roi": {"kind": "rect", "points": [[0.3543, 0.0], [0.9979, 0.9488]]},
  "oiling_roi": {"kind": "rect", "points": [[0.3543, 0.0], [0.9979, 0.9488]]},
  "detector": { ... }
}
```

| ROI | 用途 | 要求 |
| --- | --- | --- |
| `tray_roi` | 涂油盘区**底区**：判断「空手进盘、带料离盘」 | **必须覆盖盘体下方的手臂活动范围**（模型只框得出盘体本身）；运行时与模型检出的 `oil_station` 框取并集，跟随盘体上下移动 |
| `work_roi` | 工作追踪区：跟踪与判定的有效范围 | 覆盖手持丝杆、刷头与操作台；区外目标不建轨迹 |
| `oiling_roi` | 涂油区：本轮只做标定与显示 | 预留给后续涂油范围约束；缺省沿用 `work_roi` |

只有中心落在 `tray_roi`（或其并上 `oil_station` 框后的范围）或 `work_roi` 内的
检测才会进入跟踪和判定。`work_roi` 缺省为整帧（`0,0`–`1,1`）。

旧配置中的 `pick_roi` 会迁移为 `tray_roi`；2.2 之前的 `hand_roi` / `oiling_roi`
（当时是手持操作区）/ `brush_roi` 取并集后迁移为 `work_roi`；
`exclude_rois`、`material_box_roi(s)`、`slot_rois`、`occlusion_rois` 不再使用，
迁移时会被删除。

### 4.7 detector

```json
{
  "kind": "yolo",
  "model_path": "model/detect/exp/weights/best.pt",
  "confidence": 0.5,
  "iou": 0.7,
  "max_det": 100,
  "imgsz": 0,
  "device": "auto",
  "half": false,
  "raw_mode": false,
  "screw_label": "screw",
  "hand_label": "hand",
  "brush_label": "brush",
  "tray_label": "oil_station"
}
```

| 字段 | 说明 |
| --- | --- |
| `kind` | `null`（无模型，不产生检测）或 `yolo`（Ultralytics 权重） |
| `model_path` | 相对仓库根或绝对路径；相对路径由 `resolve_runtime_file` 解析 |
| `imgsz` | `0` = 自适应权重里训练时的尺寸；非 0 时按 stride 向上取整 |
| `device` | `auto`（默认）= 有 CUDA 用 `cuda:0`，否则 `cpu`；也可显式写 `cpu` / `cuda:0` / `0` |
| `half` | FP16 推理，仅在 CUDA 上生效 |
| `raw_mode` | 默认 `false`（完整 SOP 判定）。`true` = 旁路模式，只交出全量检测结果、不产生任何事件，仅用于现场核对模型标签覆盖 |

**类别名必须与训练导出模型一致。** 当前 `best.pt` 的 4 个类别：

| id | 名称 | 配置字段 |
| --- | --- | --- |
| 0 | `hand` | `hand_label` |
| 1 | `brush` | `brush_label` |
| 2 | `oil_station` | `tray_label` |
| 3 | `screw` | `screw_label` |

- `tray_label` 字段名沿用 `tray`，因为流水线里涂油盘一律以“盘体/取料参考区”
  语义处理；值填模型实际输出的 `oil_station`。
- 旧字段 `rod_label` → `screw_label`，`brush_head_label` → `brush_label`，
  读取时自动迁移。
- `brush_point_offset_x/y`：模型只输出刷具框、没有关键点时，用框内相对坐标
  估计刷头工作端（默认 `0.5` / `0.9`）。
- `cycle_seconds` 已随脚本演示检测器一并移除。

### 4.8 demo：示例视频

```json
{
  "loop": true,
  "fps_limit": 15,
  "speed": 1.0,
  "videos": [
    {"name": "示例① 105708", "path": "data/sample_video/cam_6ca47a_20261027_105708.mp4"},
    {"name": "示例② 140911", "path": "data/sample_video/cam_6ca47a_20261027_140911.mp4"}
  ]
}
```

| 字段 | 默认 | 含义 |
| --- | --- | --- |
| `loop` | true | 播放结束后从头循环 |
| `fps_limit` | 15 | 解码/投放的最大帧率（原速上限） |
| `speed` | 1.0 | 播放速率倍数，0.1~4.0；监控页顶部“速率”下拉可临时改（0.5× / 1× / 2×） |

- 画面来源是视频文件，检测仍由训练好的模型完成，不再有脚本伪造的检测框；
- `name` 显示在监控页“画面源”下拉里，`path` 同样按仓库根解析；
- 示例回放**不写入训练录制**；
- `videos` 为空时下拉里只有“实时相机”；
- 视频文件（`*.mp4`）不入版本库，`git clone` 后需手工把录像放到
  `data/sample_video/`；目录下的 `*.json` 元数据是被跟踪的；
- 运行中改了 `demo.videos` 不需要重启：配置文件变化后服务层自动重载，
  监控页下一次状态刷新就会重建“画面源”下拉；
- **变速只改播放快慢，不改判定结果**：判定计时用视频媒体时间（每帧前进
  `1/native_fps`），所以 0.5× 慢放时 `pick_confirm_s` / `brush_hold_s` 对应的
  画面时间与 1× 一致，不会因为看得慢而把「刷一下就过」判成完成。

## 5. ROI 坐标与标定

### 5.1 坐标定义

ROI 使用相对原始视频帧的归一化坐标（0~1），支持矩形和多边形。预览窗口缩放
不影响坐标。工位有三个区域：涂油盘区（`tray_roi`）、工作追踪区（`work_roi`）
与涂油区（`oiling_roi`）。

### 5.2 现场标定步骤

两种画面源任选其一，标定结果完全等价：

1. 设置页 → “打开 ROI 标定”；
2. 选择画面源：
   - **实时相机**：打开相机 → 截取画面；
   - **示例视频**：在顶部“画面源”选择 `demo.videos` 里登记的视频 → 拖动
     “视频位置”即可切换帧，无需连接相机；
3. 依次选择“涂油盘区 / 工作追踪区 / 涂油区”，拖拽矩形（前两个必填）；
4. 保存并应用，检测服务自动重载配置。

示例视频本身来自同一工位相机，分辨率与现场一致，因此可直接用它的某一帧
（如涂油盘停在典型位置、刷具在接触范围内）划取区域；现场没有相机或相机
不便暂停时推荐用这种方式。ROI 保存为归一化坐标，与视频帧率、播放位置无关。

### 5.3 常见问题

- 工作追踪区要紧贴实际作业范围，不要给太多余量，否则区外干扰目标也被跟踪；
- 工作追踪区外的目标完全不参与推理：标注数据集也按同样范围裁剪；
- 涂油盘区与检测盘体取并集：盘体上下移动时跟踪范围跟着走，短时丢失回退固定 ROI；
- 涂油区本轮不参与判定，不标定也能正常判定（缺省等于工作追踪区）。
